Ports & Portbereiche AP1 AP2

Einstieg

Ein Mehrfamilienhaus hat eine einzige Hausadresse — aber jede Wohnung darin eine eigene Tür mit eigener Wohnungsnummer. Post an die Hausadresse allein reicht nicht: Erst die Wohnungsnummer sagt, bei wem im Haus sie ankommen soll. Genauso funktioniert ein Port: Die IP-Adresse ist die Hausadresse des Geräts, der Port die Nummer der „Tür“, hinter der eine bestimmte Anwendung auf Daten wartet.

Konzept

Ein Port ist eine 16-Bit-Nummer (0–65535), die innerhalb eines Geräts festlegt, welche Anwendung für eingehende Daten zuständig ist — die IP-Adresse identifiziert das Gerät, der Port identifiziert den Dienst darauf. Sowohl TCP als auch UDP nutzen Ports, um mehrere gleichzeitige Verbindungen bzw. Dienste auf demselben Gerät sauber voneinander zu trennen.

BereichBezeichnungBeispiele
0–1023Well-Known Ports80 (HTTP), 443 (HTTPS), 22 (SSH), 25 (SMTP), 53 (DNS)
1024–49151Registered Portsvon Softwareherstellern registrierte Dienste
49152–65535Dynamic/Private Portstemporär vom Client für ausgehende Verbindungen genutzt

Auf der Server-Seite lauschen Dienste meist auf einem festen, bekannten Port (Well-Known Port) — ein Webserver z. B. auf Port 80/443, ein SSH-Dienst auf Port 22. Auf der Client-Seite wählt das Betriebssystem für jede ausgehende Verbindung automatisch einen freien dynamischen Port aus dem oberen Bereich — dadurch kann ein Gerät gleichzeitig mehrere Verbindungen zum selben Zielserver offen halten, ohne dass sich die Antworten vermischen.

Praxisbeispiel

Ein Server im Rechenzentrum eines IT-Systemhauses stellt gleichzeitig mehrere Dienste bereit: eine Firmenwebseite, einen Mailserver und einen SSH-Zugang für die Administration.

  • Anfragen an Port 443 werden vom Betriebssystem an den Webserver-Prozess weitergeleitet.
  • Anfragen an Port 25 werden an den Mailserver-Prozess weitergeleitet.
  • Eine Verbindung auf Port 22 geht an den SSH-Dienst, über den Administratoren sich aus der Ferne einloggen.
  • Alle drei Dienste laufen unter derselben IP-Adresse — allein der Zielport entscheidet, welcher Dienst die eingehenden Pakete erhält.

Typische Prüfungsfrage: „Warum kann ein Client gleichzeitig mehrere Verbindungen zu demselben Webserver aufbauen (z. B. mehrere Browser-Tabs), ohne dass sich die Antworten vermischen?“ – Antwort: Jede Verbindung nutzt clientseitig einen eigenen, vom Betriebssystem vergebenen dynamischen Port — die Kombination aus IP-Adresse und Port macht jede Verbindung eindeutig unterscheidbar.

Merksatz

Ports (0–65535) identifizieren die zuständige Anwendung auf einem Gerät. 0–1023 = Well-Known Ports (feste Standarddienste), 1024–49151 = Registered Ports, 49152–65535 = dynamische Ports für ausgehende Client-Verbindungen.
