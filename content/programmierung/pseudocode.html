Einstieg

Ein Kochrezept wird zuerst in Alltagssprache aufgeschrieben — „Zwiebeln anbraten, bis sie glasig sind“ — bevor es an eine konkrete Küchenausstattung angepasst wird. Genauso wird ein Algorithmus zuerst in Pseudocode festgehalten: die einzelnen Schritte und Entscheidungen werden aufgeschrieben, ohne sich schon auf eine bestimmte Programmiersprache festzulegen.

Konzept

Pseudocode ist eine informelle, sprachneutrale Notation, um einen Algorithmus in einzelnen Schritten zu beschreiben — ohne sich an die exakte Syntax einer bestimmten Programmiersprache zu halten. Es gibt keine einzige „richtige“ Pseudocode-Syntax; wichtig ist nur, dass der Ablauf für Menschen eindeutig nachvollziehbar bleibt.

Wozu in der Abschlussprüfung

Aufgaben wie „Schreibe in Pseudocode einen Algorithmus, der …“ verlangen keine lauffähige Syntax einer konkreten Sprache. Bewertet wird die Logik — Schritte, Bedingungen, Reihenfolge —, nicht ob z. B. Python- oder Java-Syntax exakt eingehalten wurde.

Abgrenzung zu PAP, Struktogramm und echtem Code

Pseudocode, PAP und Struktogramm können denselben Algorithmus darstellen — nur in unterschiedlicher Form:

FormDarstellung
PseudocodeFließtext in Schritten, sprachneutral
PAPgenormte grafische Symbole, durch Pfeile verbunden
Struktogrammverschachtelte Kästen ohne Pfeile
Echter Codekonkrete Programmiersprache mit fester Syntax, durch Compiler/Interpreter ausführbar

Anders als echter Code braucht Pseudocode keinen Compiler oder Interpreter — er ist nicht zum Ausführen gedacht, sondern zum Festhalten und Kommunizieren einer Lösungsidee, unabhängig davon, in welcher Sprache sie später umgesetzt wird.

Grundelemente

Eine durchgängige Notation erleichtert das Lesen. Die wichtigsten Bausteine:

ElementNotationBeispiel
ZuweisungVariable = WertMenge = 120
AusgabeAUSGABE WertAUSGABE Ergebnis
VerzweigungWENN Bedingung DANN … SONST … ENDE WENNsiehe Praxisbeispiel

Praxisbeispiel

Ein Getränkeautomat soll vor der Ausgabe prüfen, ob genug Guthaben eingeworfen wurde und ob das Produkt noch vorrätig ist:

ALGORITHMUS GetraenkAusgeben(Guthaben, Preis, Bestand) WENN Bestand == 0 DANN AUSGABE "Ausverkauft" SONST WENN Guthaben < Preis DANN AUSGABE "Guthaben nicht ausreichend" SONST Bestand = Bestand - 1 AUSGABE "Produkt wird ausgegeben" ENDE WENN RÜCKGABE Bestand

Die Reihenfolge der Prüfungen ist bewusst gewählt: zuerst wird geprüft, ob überhaupt noch Bestand da ist — erst danach, ob das Guthaben reicht. Für die Bewertung in der AP wäre genau diese Ablauflogik entscheidend, nicht die konkrete Schreibweise der Zeilen.

Übungsaufgabe

Schreibe in Pseudocode einen Algorithmus, der prüft, ob eine eingegebene Temperatur im sicheren Bereich für einen Serverraum liegt (zwischen 18 und 27 Grad, jeweils einschließlich). Ausgabe: „Normal“ oder „Alarm“.

Musterlösung anzeigen 
ALGORITHMUS TemperaturPruefen(Temperatur)
  WENN (Temperatur >= 18) UND (Temperatur <= 27) DANN
    AUSGABE "Normal"
  SONST
    AUSGABE "Alarm"
  ENDE WENN

Eine zweiseitige Verzweigung reicht hier aus: der UND-Operator verknüpft die beiden Bereichsgrenzen zu einer einzigen Bedingung, kein SONST-WENN nötig.

Merksatz

Pseudocode = informelle, sprachneutrale Beschreibung eines Algorithmus in Schritten, unabhängig von einer konkreten Programmiersprache und ohne Compiler/Interpreter ausführbar. In der AP wird die Logik bewertet, nicht die exakte Syntax einer Sprache. Dient als Vorstufe zu PAP, Struktogramm oder echtem Code — alle können denselben Algorithmus darstellen, nur in unterschiedlicher Form.
