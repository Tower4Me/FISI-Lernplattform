Die Tabellen sind angelegt und gefüllt. Jetzt will die Praxisleitung Antworten: Welche Hunde sind bei uns? Welche Tiere wiegen mehr als 20 kg? Jede dieser Fragen formulierst du als Abfrage mit SELECT. Das DBMS sucht die passenden Zeilen heraus und liefert sie als Ergebnistabelle.

Aufbau einer Abfrage

SELECT name, tierart
FROM tier
WHERE tierart = 'Hund'
ORDER BY name;
  • SELECT nennt die Spalten des Ergebnisses; * steht für alle Spalten.
  • FROM nennt die Tabelle.
  • WHERE filtert die Zeilen; nur Zeilen, für die die Bedingung zutrifft, kommen ins Ergebnis.
  • ORDER BY sortiert, aufsteigend (ASC, Standard) oder absteigend (DESC).

Ergebnis: Bello, Luna, Rocky, jeweils mit der Tierart Hund. Texte und Datumsangaben stehen in einfachen Anführungszeichen, Zahlen ohne.

Ergebnis gestalten

  • DISTINCT entfernt doppelte Zeilen: SELECT DISTINCT tierart FROM tier liefert jede Tierart einmal: Hund, Kaninchen, Katze (ohne ORDER BY in beliebiger Reihenfolge).
  • AS gibt einer Spalte einen anderen Namen im Ergebnis: SELECT name AS tiername.
  • Die ersten n Zeilen: in MariaDB, MySQL und PostgreSQL mit LIMIT n am Ende, in Microsoft SQL Server mit SELECT TOP n, im SQL-Standard mit FETCH FIRST n ROWS ONLY.

Beispiel

Die Praxisleitung fragt nach den zwei schwersten Hunden. Die Auszubildende schreibt für MariaDB:

SELECT name, gewicht_kg
FROM tier
WHERE tierart = 'Hund' AND gewicht_kg IS NOT NULL
ORDER BY gewicht_kg DESC
LIMIT 2;

Ergebnis: Bello mit 31.50 kg, Luna mit 24.00 kg. Ohne IS NOT NULL stünde Rocky in manchen Systemen wie PostgreSQL ganz oben, weil NULL dort beim absteigenden Sortieren zuerst kommt.

„WHERE gewicht_kg = NULL findet Tiere ohne Gewicht.“ Ein Vergleich mit NULL ergibt nie wahr, auch nicht mit =. Leere Felder findest du nur mit IS NULL.

Eine Abfrage nennt mit SELECT die Spalten, mit FROM die Tabelle, filtert mit WHERE (Vergleich, BETWEEN, IN, LIKE, IS NULL) und sortiert mit ORDER BY.
