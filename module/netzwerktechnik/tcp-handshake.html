TCP 3-Way-Handshake AP1 AP2

Einstieg

Am Telefon vergewissern sich zwei Gesprächspartner oft erst, ob die Verbindung überhaupt funktioniert, bevor das eigentliche Gespräch beginnt: Person A fragt „Hallo, hörst du mich?“. Person B antwortet „Ja, ich höre dich — hörst du mich auch?“. Erst wenn Person A ebenfalls bestätigt „Ja, ich höre dich“, redet man über das eigentliche Thema. Drei Wortmeldungen, bevor der eigentliche Inhalt ausgetauscht wird — genau nach diesem Muster baut auch TCP eine Verbindung auf, bevor die ersten Nutzdaten fließen.

Konzept

Bevor TCP tatsächlich Daten überträgt, bauen beide Seiten die Verbindung in drei Schritten auf — dem sogenannten 3-Way-Handshake:

  1. SYN — Der Client sendet ein Segment mit gesetztem SYN-Flag („Synchronize“) und schlägt eine Startsequenznummer vor: „Ich möchte eine Verbindung aufbauen.“
  2. SYN-ACK — Der Server antwortet mit gesetztem SYN- und ACK-Flag: „Verstanden, ich bin bereit, hier ist meine eigene Startsequenznummer.“
  3. ACK — Der Client bestätigt mit gesetztem ACK-Flag: „Verstanden, Verbindung steht.“ Erst jetzt beginnt der eigentliche Datenaustausch.

4-Way-Handshake (TCP-Verbindungsabbau)

Der Verbindungsabbau läuft spiegelbildlich zum Aufbau, aber in vier statt drei Schritten — weil TCP eine Vollduplex-Verbindung ist und jede Richtung einzeln beendet werden muss:

  1. FIN — Der Client sendet ein Segment mit gesetztem FIN-Flag („Finish“): „Ich bin fertig mit Senden.“
  2. ACK — Der Server bestätigt den Empfang: „Verstanden.“ Der Server kann in diesem Moment noch weiter Daten an den Client senden.
  3. FIN — Sobald auch der Server fertig ist, sendet er selbst ein Segment mit FIN-Flag: „Jetzt bin auch ich fertig.“
  4. ACK — Der Client bestätigt den Empfang: „Verstanden, Verbindung wird geschlossen.“ Erst jetzt ist die Verbindung vollständig beendet.

Die Portnummern, über die eine solche Verbindung eine bestimmte Anwendung adressiert, behandelt die Einheit Ports & Portbereiche.

Praxisbeispiel

Ein Kunde meldet: „Ich kann die neue Firmenwebseite nicht öffnen, aber ping auf den Server funktioniert.“

  • ping nutzt ICMP, nicht TCP — ein erfolgreicher Ping zeigt nur, dass der Server grundsätzlich erreichbar ist, sagt aber nichts über einen bestimmten Dienst aus.
  • Ein Mitschnitt des Datenverkehrs zeigt: Der Browser sendet ein SYN-Paket an Port 443, aber es kommt kein SYN-ACK zurück — der Handshake bleibt im ersten Schritt stecken.
  • Fazit: Der Server selbst ist erreichbar (Ping funktioniert), aber der Webserver-Dienst auf Port 443 antwortet nicht — z. B. weil eine Firewall den Port blockiert oder der Webserver-Dienst nicht läuft.

Typische Prüfungsfrage: „Woran erkennt man in einem Netzwerkmitschnitt, dass ein TCP-Verbindungsaufbau fehlgeschlagen ist?“ – Antwort: Es wird zwar ein SYN-Paket gesendet, aber es folgt kein SYN-ACK vom Zielsystem — der Handshake bricht nach dem ersten Schritt ab.

Merksatz

TCP-Verbindungsaufbau = 3-Way-Handshake: SYN, SYN-ACK, ACK. Erst danach fließen Nutzdaten. Der Abbau braucht vier Schritte (FIN, ACK, FIN, ACK), weil beide Übertragungsrichtungen einzeln beendet werden müssen.
