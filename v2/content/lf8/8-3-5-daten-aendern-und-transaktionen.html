Beim Prüfen der Datenqualität (Kapitel 8.1.4) ist eine Dublette aufgefallen: Frau Yilmaz steht in der zentralen Datenbank zweimal, unter der zentralen Nummer 2 (Datensatz aus dem Stammhaus) und der zentralen Nummer 9 (Datensatz vom Standort Nord). Unter Nummer 9 sind zwei ihrer Tiere eingetragen, die nicht zum Ausschnitt aus Kapitel 8.3.1 gehören. Du sollst die beiden Einträge zusammenführen. Dafür fügst du Daten ein, änderst und löschst sie und sorgst dafür, dass dabei nichts halb erledigt bleibt.

Einfügen, ändern, löschen

INSERT INTO besitzer (besitzer_id, name, ort, telefon)
VALUES (9, 'Yilmaz', 'Halle', '0345 7654321');

UPDATE tier
SET besitzer_id = 2
WHERE besitzer_id = 9;

DELETE FROM besitzer
WHERE besitzer_id = 9;
  • INSERT INTO fügt eine Zeile ein. Die Werte stehen in derselben Reihenfolge wie die genannten Spalten. Nicht genannte Spalten bekommen ihren DEFAULT oder werden NULL; ist eine solche Spalte NOT NULL und hat keinen DEFAULT, lehnt das DBMS das Einfügen ab.
  • UPDATE … SET ändert Werte in allen Zeilen, die die WHERE-Bedingung erfüllen.
  • DELETE FROM löscht alle Zeilen, die die Bedingung erfüllen. Verweisen noch andere Zeilen darauf, lehnt das DBMS das Löschen ohne ON-DELETE-Regel ab (Kapitel 8.2.3).

Das INSERT oben zeigt, wie die Dublette beim Übernehmen entstanden ist. Zum Zusammenführen brauchst du nur das UPDATE und das DELETE.

„UPDATE tier SET besitzer_id = 2 ändert schon das Richtige.“ Ohne WHERE gelten UPDATE und DELETE für jede Zeile der Tabelle: Alle Tiere gehörten danach Frau Yilmaz. Prüfe die Bedingung vorher mit einem SELECT, das dieselbe WHERE-Bedingung hat.

Transaktionen

Die beiden Schritte gehören zusammen. Bricht die Verbindung nach dem UPDATE ab, sind die Tiere schon umgehängt, der doppelte Eintrag aber noch da. Läuft das DELETE zuerst, scheitert es an den Tieren, die noch auf Nummer 9 verweisen. Damit mehrere Befehle nur gemeinsam wirken, fasst du sie zu einer Transaktion zusammen:

START TRANSACTION;
UPDATE tier SET besitzer_id = 2 WHERE besitzer_id = 9;
DELETE FROM besitzer WHERE besitzer_id = 9;
COMMIT;

COMMIT schreibt alle Änderungen der Transaktion endgültig fest. ROLLBACK macht sie alle rückgängig, etwa wenn ein Befehl einen Fehler meldet. Je nach System beginnt eine Transaktion mit START TRANSACTION oder BEGIN. Ohne ausdrücklich begonnene Transaktion schreiben viele Systeme jeden Befehl sofort fest (Autocommit).

Beispiel

Die Auszubildende führt zuerst SELECT * FROM tier WHERE besitzer_id = 9 aus und sieht zwei Tiere. Dann startet sie die Transaktion. Das UPDATE meldet „2 Zeilen geändert“, das DELETE „1 Zeile gelöscht“. Beides passt zur Erwartung, also schließt sie mit COMMIT ab. Hätte das UPDATE 200 Zeilen gemeldet, hätte sie mit ROLLBACK abgebrochen.

INSERT fügt ein, UPDATE ändert, DELETE löscht; UPDATE und DELETE nie ohne WHERE. Eine Transaktion lässt zusammengehörige Befehle mit COMMIT gemeinsam gelten oder mit ROLLBACK gemeinsam verfallen.
