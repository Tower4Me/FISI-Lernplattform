3.5Dienste und Protokolle

AP1LF3: Clients in Netzwerke einbinden

3.5.1 DHCP

Bei zwei Geräten kannst du Adressen noch von Hand eintragen. Sobald Notebooks, Smartphones und Gäste dazukommen, wird das fehleranfällig: doppelte Adressen, falsche Gateways. DHCP verteilt die Konfiguration automatisch und an einer Stelle. Deshalb ist es in fast jedem Netz eingeschaltet, meist im Router.

Was DHCP verteilt#

Ein DHCP-Server (Dynamic Host Configuration Protocol) gibt einem Client auf Anfrage eine vollständige IPv4-Konfiguration:

  • IP-Adresse und Subnetzmaske
  • Standardgateway
  • DNS-Server (Kapitel 3.5.2)
  • die Lease-Zeit: wie lange der Client die Adresse nutzen darf

Der Server vergibt Adressen aus einem festgelegten Bereich (Pool), etwa 192.168.10.100 bis 192.168.10.199. Adressen außerhalb des Bereichs bleiben für Geräte mit fester Adresse frei, etwa Router, NAS und Drucker.

Ablauf: DORA#

Ein neuer Client kennt weder seine Adresse noch den Server. Deshalb beginnt er mit einem Broadcast:

  1. Discover: Der Client fragt per Broadcast ins Netz: „Gibt es einen DHCP-Server?“
  2. Offer: Der Server bietet eine freie Adresse samt Konfiguration an.
  3. Request: Der Client fordert die angebotene Adresse an; weil mehrere Server geantwortet haben könnten, ebenfalls per Broadcast.
  4. Acknowledge: Der Server bestätigt, der Client richtet die Adresse ein.

Nach der Hälfte der Lease-Zeit bittet der Client seinen Server direkt (Unicast), die Lease zu verlängern; dafür reichen Request und Acknowledge. Antwortet der Server nicht, fragt der Client nach 87,5 % der Lease-Zeit per Broadcast jeden DHCP-Server. Läuft die Lease ab, muss er die Adresse aufgeben. DHCP läuft über UDP, der Server lauscht auf Port 67, der Client auf Port 68.

Weil Discover ein Broadcast ist, erreicht er nur das eigene Netz. Steht der Server in einem anderen Netz, leitet ein DHCP-Relay im Router die Anfragen weiter. Antwortet kein DHCP-Server, gibt sich der Client eine 169.254er-Adresse (APIPA, Kapitel 3.4.5).

Reservierung#

Soll ein Gerät immer dieselbe Adresse bekommen, aber trotzdem per DHCP eingerichtet werden, legst du im Server eine Reservierung an: eine feste Zuordnung von MAC-Adresse zu IP-Adresse. Das ist praktisch für Drucker, deren Adresse sich nicht ändern darf, die aber zentral verwaltet werden sollen. Viele Router erlauben Reservierungen auch außerhalb des Bereichs; bei Windows Server muss die Adresse im Bereich liegen. Nutzt ein Gerät im WLAN eine zufällige MAC-Adresse, greift die Reservierung nicht; diese Funktion schaltest du dafür ab (Kapitel 3.3.5).

Beispiel

Nach dem Engpass aus Kapitel 3.4.5 legt die Auszubildende die DHCP-Einstellungen im Router neu fest: Bereich 192.168.10.100 bis .199 (100 Adressen), Gateway und DNS-Server 192.168.10.1, Lease-Zeit ein Tag. Router (.1), Access Point (.5), NAS (.10) und Drucker (.20) liegen außerhalb des Bereichs. Für den Drucker legt sie zusätzlich eine Reservierung auf seine MAC-Adresse an, damit er die .20 auch bekommt, wenn jemand ihn auf „automatisch“ zurückstellt.

Häufiger Fehler

„Zwei DHCP-Server sind doppelt sicher.“ Nicht ohne Abstimmung: Verteilen zwei Server im selben Netz Adressen aus überlappenden Bereichen, entstehen doppelte Adressen. Ein vergessener zweiter DHCP-Server, etwa in einem mitgebrachten WLAN-Router, ist ein typischer Störenfried.

Merksatz

  • DHCP verteilt Adresse, Maske, Gateway, DNS-Server und Lease-Zeit aus einem Bereich.
  • DORA: Discover (Broadcast), Offer, Request, Acknowledge; UDP 67/68; feste Zuordnung per Reservierung über die MAC-Adresse.

3.5.2 DNS

Menschen merken sich Namen, Rechner arbeiten mit Adressen. Das Domain Name System übersetzt zwischen beiden. Fällt DNS aus, wirkt es, als sei „das Internet weg“, obwohl alle Verbindungen funktionieren. Mit diesem Wissen findest du solche Fehler schnell.

Wozu DNS dient#

Das DNS (Domain Name System) löst Namen wie www.beispiel.de in IP-Adressen auf. Es ist eine weltweit verteilte Datenbank: Kein Server kennt alle Namen, aber jeder weiß, wen er fragen kann.

Namen sind hierarchisch aufgebaut und werden von rechts gelesen: de ist die Top-Level-Domain, beispiel die Second-Level-Domain darunter, www ein Rechner oder Dienst in dieser Domain. Ganz rechts steht, meist unsichtbar, die Wurzel (Root) als Punkt. Der vollständige Name www.beispiel.de. heißt FQDN (Fully Qualified Domain Name).

So läuft eine Auflösung#

  1. Der Client schaut in seinen eigenen Zwischenspeicher (Cache) und in die lokale Datei hosts (unter Windows C:\Windows\System32\drivers\etc\hosts).
  2. Findet er nichts, fragt er den in seiner Konfiguration eingetragenen DNS-Server, im Büro meist den Router.
  3. Der Router löst den Namen meist nicht selbst auf, sondern leitet die Anfrage an den DNS-Server des Providers weiter (Forwarder). Dieser fragt, falls nötig, der Reihe nach einen Root-Server, den Server für .de und den Server, der für beispiel.de zuständig ist. Jeder nennt ihm nur den nächsten Ansprechpartner (iterative Abfrage); der Client dagegen erwartet eine fertige Antwort (rekursive Abfrage).
  4. Die Antwort geht an den Client zurück und wird für eine im Eintrag festgelegte Zeit (TTL, Time to Live) zwischengespeichert. Deshalb wirken geänderte Einträge nicht sofort; den Cache leerst du mit ipconfig /flushdns.

DNS nutzt Port 53, für normale Anfragen meist UDP, für große Antworten und die Übertragung ganzer Zonen zwischen Servern TCP.

Einträge#

EintragBedeutungBeispiel
AName zu IPv4-Adressewww → 203.0.113.10
AAAAName zu IPv6-Adressewww → 2001:db8::10
CNAMEName ist ein Alias für einen anderen Namenshop → www
MXzuständiger Mailserver der Domainbeispiel.de → mail.beispiel.de
PTRumgekehrt: Adresse zu Name203.0.113.10 → www.beispiel.de

Beispiel

Der Mitarbeiter meldet: „Keine Webseite geht.“ Der Auszubildende testet: ping 8.8.8.8 funktioniert, ping www.beispiel.de meldet „Host nicht gefunden“. Die Verbindung ins Internet steht also, nur die Namensauflösung fehlt. Im Notebook ist als DNS-Server eine alte Adresse von Hand eingetragen. Nach dem Umstellen auf „automatisch beziehen“ bekommt es per DHCP den Router als DNS-Server, und alles läuft.

Häufiger Fehler

„Wenn Webseiten nicht laden, ist das Internet weg.“ Nicht unbedingt: Klappt der Zugriff über die IP-Adresse, aber nicht über den Namen, liegt der Fehler beim DNS. Prüfen kannst du das mit nslookup (Kapitel 3.7.2).

Merksatz

  • DNS löst Namen in IP-Adressen auf; hierarchisch, verteilt, Port 53.
  • Einträge: A (IPv4), AAAA (IPv6), CNAME (Alias), MX (Mailserver), PTR (Adresse zu Name).
  • Fehlerbild: IP-Adresse erreichbar, Name nicht, dann liegt es am DNS.

3.5.3 ARP

Ein PC kennt die IP-Adresse des Druckers. Um ihm einen Ethernet-Rahmen zu schicken, braucht er aber dessen MAC-Adresse. Diese Lücke schließt ARP. Wenn du verstehst, wie es arbeitet, kannst du die ARP-Tabelle eines Rechners lesen und manche Fehler direkt erkennen.

Wie ARP arbeitet#

ARP (Address Resolution Protocol) ermittelt zu einer IPv4-Adresse im eigenen Netz die zugehörige MAC-Adresse.

  1. Der PC prüft seine ARP-Tabelle (ARP-Cache). Steht die Zuordnung dort, nutzt er sie.
  2. Sonst schickt er eine ARP-Anfrage als Broadcast an alle: „Wer hat 192.168.10.20? Bitte an 192.168.10.104 melden.“
  3. Nur der Drucker mit dieser Adresse antwortet, direkt an den PC: „192.168.10.20 ist bei 00-1B-A9-4C-22-07.“
  4. Der PC trägt die Zuordnung in seine ARP-Tabelle ein. Einträge verfallen nach kurzer Zeit wieder, damit Änderungen auffallen.

ARP prüft nicht, ob eine Antwort echt ist. Ein Angreifer kann sich deshalb als Gateway ausgeben (ARP-Spoofing) und den Verkehr mitlesen.

Liegt das Ziel in einem anderen Netz, fragt der PC nicht nach dem Ziel, sondern nach der MAC-Adresse seines Standardgateways (Kapitel 3.4.3). Denn der Rahmen geht zuerst an den Router.

Die ARP-Tabelle ansehen#

Mit arp -a zeigt Windows die gelernten Zuordnungen:

InternetadressePhysische AdresseTyp
192.168.10.1d4-3f-cb-11-02-01dynamisch
192.168.10.2000-1b-a9-4c-22-07dynamisch
192.168.10.255ff-ff-ff-ff-ff-ffstatisch

„Dynamisch“ heißt per ARP gelernt; die Broadcastadresse ist fest eingetragen. Windows gruppiert die Tabelle nach Schnittstelle (Zeile Schnittstelle: 192.168.10.104 --- 0x…). Den Befehl übst du in Kapitel 3.7.2.

Bei IPv6 gibt es kein ARP. Diese Aufgabe übernimmt die Nachbarerkennung (Neighbor Discovery, Teil von ICMPv6) mit Multicast statt Broadcast.

Beispiel

Seit dem Einrichten eines alten Druckers aus dem Lager drucken mal die Aufträge, mal nicht. In arp -a sieht die Auszubildende, dass zu 192.168.10.20 abwechselnd zwei verschiedene MAC-Adressen eingetragen sind. Beide Drucker haben dieselbe feste Adresse. Sie gibt dem alten Drucker die freie feste Adresse 192.168.10.21 außerhalb des DHCP-Bereichs und trägt sie in die Dokumentation ein.

Häufiger Fehler

„Der PC fragt per ARP nach der MAC-Adresse des Webservers im Internet.“ Nein: ARP funktioniert nur im eigenen Netz. Für fremde Ziele fragt der PC nach der MAC-Adresse seines Gateways.

Merksatz

  • ARP: IPv4-Adresse zu MAC-Adresse im eigenen Netz; Anfrage per Broadcast, Antwort direkt; Ergebnis im ARP-Cache (arp -a).
  • Fremde Netze: ARP nach dem Gateway; bei IPv6 übernimmt Neighbor Discovery.

3.5.4 TCP, UDP und Ports

Auf einem Server laufen gleichzeitig Webseite, Mail und Dateifreigabe, alle unter derselben IP-Adresse. Woher weiß der Server, welches Programm ein Paket bekommt? Über die Portnummer. Und ob die Daten garantiert ankommen müssen oder schnell sein sollen, entscheidet die Wahl zwischen TCP und UDP.

Ports#

Ein Port ist eine Nummer von 0 bis 65535, die ein Programm auf einem Rechner kennzeichnet. Die Kombination aus IP-Adresse und Port, etwa 192.168.10.10:445, heißt Socket; dazu gehört noch das Protokoll TCP oder UDP. Eine Verbindung ist durch zwei Sockets eindeutig bestimmt: den des Clients und den des Servers.

BereichNameVerwendung
0 bis 1023Well-known PortsStandarddienste wie HTTP (80) oder HTTPS (443)
1024 bis 49151Registered Portsbei der IANA eingetragene Anwendungen, etwa RDP (3389)
49152 bis 65535Dynamische Portsvon der IANA für zufällig gewählte Absenderports vorgesehen (Windows nutzt genau diesen Bereich, Linux standardmäßig 32768 bis 60999)

Ruft ein Browser eine Webseite auf, geht die Anfrage an Zielport 443 des Servers, vom zufälligen Absenderport des Clients, etwa 51734. Die Antwort kommt an genau diesen Port zurück.

TCP und UDP#

Bei Telefonie und Video ist ein verlorenes Stück weniger schlimm als eine Verzögerung: Ein wiederholtes Datenpaket käme zu spät, um noch zu helfen. Deshalb nutzen sie UDP.

Der Drei-Wege-Handschlag#

TCP baut jede Verbindung in drei Schritten auf:

  1. SYN: Der Client bittet um eine Verbindung.
  2. SYN-ACK: Der Server bestätigt und bittet seinerseits um die Verbindung.
  3. ACK: Der Client bestätigt. Jetzt fließen die Daten.

Abgebaut wird die Verbindung ebenfalls geordnet, mit FIN und ACK in beide Richtungen.

Beispiel

Der Mitarbeiter kann von seinem Notebook nicht mehr auf die Freigabe des NAS zugreifen, obwohl ping 192.168.10.10 antwortet. Netzwerk und Adresse sind also in Ordnung. Die Auszubildende prüft die Firewall des NAS: Nach einem Update lässt sie zwar ping durch, sperrt aber eingehende Verbindungen auf den Dateifreigabe-Port 445. Mit einer Regel, die Port 445 für 192.168.10.0/24 freigibt, klappt der Zugriff wieder. ping nutzt ICMP und keinen Port; ein erfolgreicher ping sagt deshalb nichts darüber, ob ein bestimmter Port erreichbar ist.

Häufiger Fehler

„UDP ist schlechter als TCP, weil es Daten verlieren kann.“ Nein: UDP ist für andere Zwecke gemacht. Wo Tempo wichtiger ist als Vollständigkeit oder wo kurze Anfragen einfach wiederholt werden können, ist es die bessere Wahl.

Merksatz

  • Port: kennzeichnet das Programm; 0–1023 well-known, 1024–49151 registered, ab 49152 dynamisch; IP-Adresse plus Port = Socket.
  • TCP: verbindungsorientiert und zuverlässig, Handschlag SYN, SYN-ACK, ACK; UDP: verbindungslos und schnell.

3.5.5 Anwendungsprotokolle

Ob eine Firewall-Regel stimmt, ein Mailprogramm richtig eingerichtet ist oder ein Fernzugriff klappt, hängt oft an Protokoll und Port. Die wichtigsten Anwendungsprotokolle und ihre Ports gehören deshalb zum Grundwissen. Du brauchst sie im Alltag beim Einrichten von Clients und in der Prüfung beim Zuordnen.

Wo es eine verschlüsselte Variante gibt, nutzt du sie: HTTPS statt HTTP, SSH oder SFTP statt Telnet oder FTP, IMAP und SMTP mit TLS. Unverschlüsselt übertragene Passwörter kann jeder mitlesen, der den Datenverkehr sieht.

Die URL#

Im Browser steht vor jeder Adresse das Protokoll. Eine URL (Uniform Resource Locator) ist so aufgebaut:

https://www.beispiel.de:443/kontakt/index.html?sprache=de

  • https: Protokoll (Schema)
  • www.beispiel.de: Rechnername, den DNS auflöst
  • :443: Port; meist weggelassen, wenn es der Standardport ist
  • /kontakt/index.html: Pfad zur Ressource auf dem Server
  • ?sprache=de: Parameter

Beispiel

Die Inhaberin der Hausverwaltung will ihre Mails künftig auf PC und Smartphone gleich sehen: Gelesenes soll überall als gelesen erscheinen. Der Auszubildende richtet deshalb beide Geräte mit IMAP über Port 993 ein, nicht mit POP3. Zum Versenden trägt er SMTP mit Port 587 und Verschlüsselung ein.

Häufiger Fehler

„Port 443 heißt, die Seite ist sicher.“ Nicht ganz: Port 443 und HTTPS bedeuten, dass die Verbindung verschlüsselt ist. Ob die Seite vertrauenswürdig ist, sagt das nicht; auch Betrüger nutzen HTTPS.

Merksatz

  • Ports: HTTP 80, HTTPS 443, DNS 53, DHCP 67/68, SMTP 25/587/465, IMAP 143/993, POP3 110/995, FTP 20/21, SSH 22, Telnet 23, RDP 3389, SMB 445, NTP 123.
  • Verschlüsselte Varianten bevorzugen; URL: Protokoll, Rechnername, Port, Pfad, Parameter.
