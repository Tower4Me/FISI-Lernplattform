8.3Daten mit SQL abfragen und ändern

AP2LF8: Daten systemübergreifend bereitstellen

8.3.1 Daten abfragen mit SELECT

Die Tabellen sind angelegt und gefüllt. Jetzt will die Praxisleitung Antworten: Welche Hunde sind bei uns? Welche Tiere wiegen mehr als 20 kg? Jede dieser Fragen formulierst du als Abfrage mit SELECT. Das DBMS sucht die passenden Zeilen heraus und liefert sie als Ergebnistabelle.

Die Beispieldaten#

Die Abfragen in diesem Kapitel arbeiten mit einem kleinen Ausschnitt der zentralen Datenbank:

Tabelle tier
tier_idnametierartgeburtsdatumgewicht_kgbesitzer_id
10MimiKatze2019-05-144.201
11BelloHund2016-08-0231.501
12FipsKaninchen2022-03-302.102
31LunaHund2020-11-0924.007
32RockyHund2023-01-17NULL7

Bei Rocky wurde noch kein Gewicht erfasst. NULL heißt: kein Wert eingetragen. Ein leerer Text '' oder die Zahl 0 sind dagegen Werte. Die übrigen Tabellen (besitzer, impfstoff, impfung) folgen in Kapitel 8.3.3.

Aufbau einer Abfrage#

SELECT name, tierart
FROM tier
WHERE tierart = 'Hund'
ORDER BY name;
  • SELECT nennt die Spalten des Ergebnisses; * steht für alle Spalten.
  • FROM nennt die Tabelle.
  • WHERE filtert die Zeilen; nur Zeilen, für die die Bedingung zutrifft, kommen ins Ergebnis.
  • ORDER BY sortiert, aufsteigend (ASC, Standard) oder absteigend (DESC).

Ergebnis: Bello, Luna, Rocky, jeweils mit der Tierart Hund. Texte und Datumsangaben stehen in einfachen Anführungszeichen, Zahlen ohne.

Bedingungen formulieren#

AusdruckBedeutungBeispiel
= <> < > <= >=Vergleich (<> heißt ungleich)gewicht_kg > 20
AND, OR, NOTBedingungen verknüpfen; Klammern setzen, wenn AND und OR gemischt werden, denn AND bindet stärkertierart = 'Hund' AND gewicht_kg < 25
BETWEEN … AND …Bereich, beide Grenzen eingeschlossengeburtsdatum BETWEEN '2020-01-01' AND '2022-12-31'
IN (…)Wert aus einer Listetierart IN ('Katze', 'Kaninchen')
LIKETextmuster: % beliebig viele Zeichen, _ genau ein Zeichenname LIKE 'L%' findet Luna
IS NULL, IS NOT NULLFeld hat keinen Wert oder hat einengewicht_kg IS NULL findet Rocky

Ergebnis gestalten#

  • DISTINCT entfernt doppelte Zeilen: SELECT DISTINCT tierart FROM tier liefert jede Tierart einmal: Hund, Kaninchen, Katze (ohne ORDER BY in beliebiger Reihenfolge).
  • AS gibt einer Spalte einen anderen Namen im Ergebnis: SELECT name AS tiername.
  • Die ersten n Zeilen: in MariaDB, MySQL und PostgreSQL mit LIMIT n am Ende, in Microsoft SQL Server mit SELECT TOP n, im SQL-Standard mit FETCH FIRST n ROWS ONLY.

Beispiel

Die Praxisleitung fragt nach den zwei schwersten Hunden. Die Auszubildende schreibt für MariaDB:

SELECT name, gewicht_kg
FROM tier
WHERE tierart = 'Hund' AND gewicht_kg IS NOT NULL
ORDER BY gewicht_kg DESC
LIMIT 2;

Ergebnis: Bello mit 31.50 kg, Luna mit 24.00 kg. Ohne IS NOT NULL stünde Rocky in manchen Systemen wie PostgreSQL ganz oben, weil NULL dort beim absteigenden Sortieren zuerst kommt.

Häufiger Fehler

„WHERE gewicht_kg = NULL findet Tiere ohne Gewicht.“ Ein Vergleich mit NULL ergibt nie wahr, auch nicht mit =. Leere Felder findest du nur mit IS NULL.

Merksatz

Eine Abfrage nennt mit SELECT die Spalten, mit FROM die Tabelle, filtert mit WHERE (Vergleich, BETWEEN, IN, LIKE, IS NULL) und sortiert mit ORDER BY.

8.3.2 Daten zusammenfassen

Die Praxisleitung braucht selten einzelne Tiere, sondern Zahlen: Wie viele Hunde behandeln wir? Wie schwer sind sie im Schnitt? Dafür fasst du viele Zeilen zu einem Wert zusammen. Das erledigen Aggregatfunktionen, auf Wunsch getrennt nach Gruppen.

Aggregatfunktionen#

FunktionErgebnisBeispiel mit der Tabelle tier (Kapitel 8.3.1)
COUNT(*)Anzahl ZeilenSELECT COUNT(*) FROM tier ergibt 5
COUNT(spalte)Anzahl Zeilen, in denen die Spalte einen Wert hatCOUNT(gewicht_kg) ergibt 4, Rocky fehlt
SUM(spalte)SummeSUM(gewicht_kg) ergibt 61.80
AVG(spalte)Mittelwert der vorhandenen WerteAVG(gewicht_kg) ergibt 15.45 (61.80 / 4)
MIN, MAXkleinster, größter WertMAX(gewicht_kg) ergibt 31.50

Felder ohne Wert (NULL) lassen die Funktionen aus. Deshalb teilt AVG hier durch 4, nicht durch 5. Mit WHERE kannst du vorher filtern: SELECT COUNT(*) FROM tier WHERE tierart = 'Hund' ergibt 3.

Gruppieren mit GROUP BY#

Mit GROUP BY bildet das DBMS für jeden Wert einer Spalte eine Gruppe und rechnet die Aggregatfunktion je Gruppe:

SELECT tierart, COUNT(*) AS anzahl, AVG(gewicht_kg) AS schnitt_kg
FROM tier
GROUP BY tierart
ORDER BY tierart;
Ergebnis
tierartanzahlschnitt_kg
Hund327.75
Kaninchen12.10
Katze14.20

Bei den Hunden zählt COUNT(*) drei Tiere, AVG teilt aber durch 2: (31.50 + 24.00) / 2 = 27.75, Rockys NULL fällt weg.

Regel: Jede Spalte im SELECT, die nicht in einer Aggregatfunktion steht, muss auch im GROUP BY stehen. Sonst wäre unklar, welcher der vielen Werte einer Gruppe angezeigt werden soll. MariaDB meldet ohne strenge Einstellung keinen Fehler, sondern zeigt einen beliebigen Wert der Gruppe; halte dich trotzdem an die Regel.

Gruppen filtern mit HAVING#

WHERE filtert einzelne Zeilen vor dem Gruppieren. HAVING filtert die fertigen Gruppen nach dem Gruppieren und darf deshalb Aggregatfunktionen enthalten:

SELECT tierart, COUNT(*) AS anzahl
FROM tier
WHERE geburtsdatum >= '2019-01-01'
GROUP BY tierart
HAVING COUNT(*) >= 2;

Zuerst fallen alle Tiere weg, die vor 2019 geboren sind (Bello). Dann wird gruppiert: Hund 2 (Luna, Rocky), Katze 1, Kaninchen 1. Übrig bleibt nur die Gruppe Hund mit 2.

Die Reihenfolge der Teile ist fest: SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY ….

Beispiel

Für den Jahresbericht will die Praxisleitung wissen, wie viele Impfungen 2025 je Impfstoff gegeben wurden, sortiert nach Häufigkeit:

SELECT impfstoff_id, COUNT(*) AS anzahl
FROM impfung
WHERE datum BETWEEN '2025-01-01' AND '2025-12-31'
GROUP BY impfstoff_id
ORDER BY anzahl DESC;

Ergebnis mit den Daten aus Kapitel 8.3.3: Impfstoff 3 viermal, Impfstoff 5 und 7 je einmal. Statt der Nummer soll später die Bezeichnung des Impfstoffs erscheinen. Dafür brauchst du eine zweite Tabelle im selben Ergebnis (Kapitel 8.3.3).

Häufiger Fehler

„WHERE COUNT(*) >= 2 zeigt nur Tierarten mit mindestens zwei Tieren.“ Das ist ein Fehler: Wenn WHERE ausgewertet wird, gibt es die Gruppen noch nicht. Bedingungen auf Aggregate gehören in HAVING.

Merksatz

COUNT, SUM, AVG, MIN und MAX fassen Zeilen zusammen und lassen NULL aus; GROUP BY rechnet sie je Gruppe, WHERE filtert Zeilen vor dem Gruppieren, HAVING die Gruppen danach.

8.3.3 Tabellen verknüpfen

Nach dem Normalisieren steht der Name der Besitzerin in der Tabelle besitzer, der Name des Tiers in tier. Für eine Liste „Tier und Besitzerin“ musst du beide Tabellen in einer Abfrage zusammenführen. Das leistet der JOIN: Er verbindet Zeilen über Primär- und Fremdschlüssel.

RHD ist eine Impfung für Kaninchen. Gegen Katzenseuche wurde bisher kein Tier geimpft.

INNER JOIN#

SELECT t.name AS tier, b.name AS besitzerin
FROM tier t
INNER JOIN besitzer b ON t.besitzer_id = b.besitzer_id
ORDER BY b.name;

Hinter ON steht die Verknüpfungsbedingung: Fremdschlüssel gleich Primärschlüssel. Die Kürzel t und b sind Aliasnamen für die Tabellen; sie sind nötig, weil beide Tabellen eine Spalte name haben. Der INNER JOIN liefert nur Zeilen, zu denen es in beiden Tabellen einen Partner gibt: fünf Tiere mit ihren Besitzerinnen. Frau Brandt fehlt, weil kein Tier auf sie verweist.

LEFT JOIN#

Soll jede Besitzerin erscheinen, auch ohne Tier, nimmst du einen LEFT JOIN. Er behält alle Zeilen der linken Tabelle (der vor dem JOIN) und füllt fehlende Partner mit NULL:

SELECT b.name, t.name AS tier
FROM besitzer b
LEFT JOIN tier t ON t.besitzer_id = b.besitzer_id;

Jetzt steht Brandt mit NULL als Tier im Ergebnis. Mit dem Zusatz WHERE t.tier_id IS NULL findest du gezielt alle Besitzerinnen ohne Tier. Ein RIGHT JOIN behält entsprechend alle Zeilen der rechten Tabelle.

Drei Tabellen verknüpfen#

Die Zwischentabelle impfung wird mit beiden Seiten verbunden, je ein JOIN pro Verknüpfung:

SELECT t.name, s.bezeichnung, i.datum
FROM impfung i
INNER JOIN tier t      ON i.tier_id = t.tier_id
INNER JOIN impfstoff s ON i.impfstoff_id = s.impfstoff_id
WHERE i.datum < '2025-04-01' AND t.name LIKE 'L%';

Ergebnis: Luna mit Tollwut und Luna mit Staupe, beide am 2025-03-04. Für n Tabellen brauchst du n − 1 Verknüpfungsbedingungen.

Beispiel

Ein Kollege schreibt die Abfrage in der älteren Form ohne JOIN: SELECT t.name, b.name FROM tier t, besitzer b WHERE t.besitzer_id = b.besitzer_id. Das liefert dasselbe wie der INNER JOIN. Vergisst er die Bedingung, kombiniert das DBMS jede Zeile mit jeder: 5 Tiere × 4 Besitzerinnen = 20 Zeilen, die meisten davon falsch. Diese Kombination heißt kartesisches Produkt. Die Auszubildende schreibt deshalb immer JOIN … ON: Beim Lesen fällt eine fehlende ON-Zeile sofort auf, PostgreSQL meldet sogar einen Fehler.

Häufiger Fehler

„Der JOIN erkennt die Verknüpfung selbst am Fremdschlüssel.“ Nein: Die Bedingung hinter ON musst du angeben. Der Fremdschlüssel sichert nur, dass die Werte gültig sind.

Merksatz

  • INNER JOIN: nur Zeilen mit Partner in beiden Tabellen, verknüpft mit ON Fremdschlüssel = Primärschlüssel.
  • LEFT JOIN: alle Zeilen der linken Tabelle, fehlende Partner als NULL.
  • Zwei Tabellen ohne Verknüpfungsbedingung ergeben das kartesische Produkt (m × n Zeilen).

8.3.4 Unterabfragen und Sichten

Manche Fragen lassen sich nicht in einem Schritt beantworten. „Welche Tiere sind schwerer als der Durchschnitt?“ setzt voraus, dass du den Durchschnitt erst kennst. Solche Abfragen baust du aus einer inneren und einer äußeren Abfrage. Und wenn eine Abfrage immer wieder gebraucht wird, speicherst du sie als Sicht.

Unterabfragen#

Eine Unterabfrage ist ein SELECT in Klammern innerhalb einer anderen Abfrage. Das DBMS wertet sie aus und setzt ihr Ergebnis in die äußere Abfrage ein.

Ein einzelner Wert, verglichen mit =, < oder >:

SELECT name, gewicht_kg
FROM tier
WHERE gewicht_kg > (SELECT AVG(gewicht_kg) FROM tier);

Die innere Abfrage liefert 15.45 (Kapitel 8.3.2). Ergebnis: Bello (31.50) und Luna (24.00).

Eine Liste von Werten, geprüft mit IN oder NOT IN:

SELECT bezeichnung
FROM impfstoff
WHERE impfstoff_id NOT IN (SELECT impfstoff_id FROM impfung);

Die innere Abfrage liefert alle Impfstoffnummern, die schon verwendet wurden (3, 5, 7). Ergebnis: Katzenseuche, der einzige Impfstoff ohne Impfung. Dieselbe Frage lässt sich auch mit einem LEFT JOIN und IS NULL beantworten (Kapitel 8.3.3); beide Wege sind üblich.

Daneben gibt es EXISTS: Es prüft für jede Zeile der äußeren Abfrage, ob die Unterabfrage mindestens eine Zeile liefert. Die Unterabfrage bezieht sich dazu auf die äußere Zeile:

SELECT name
FROM besitzer b
WHERE NOT EXISTS (SELECT * FROM tier t WHERE t.besitzer_id = b.besitzer_id);

Ergebnis: Brandt, die einzige Besitzerin ohne Tier.

Hinweis

Liefert die Unterabfrage bei NOT IN auch nur einen NULL-Wert, ergibt die ganze Abfrage keine einzige Zeile. Im Beispiel kann das nicht passieren, weil impfstoff_id zum Primärschlüssel von impfung gehört. Bei Spalten, die leer sein dürfen, nimmst du besser NOT EXISTS oder LEFT JOIN mit IS NULL.

Sichten#

Eine Sicht (englisch View) ist eine gespeicherte Abfrage mit einem Namen. Man fragt sie ab wie eine Tabelle, sie speichert aber keine eigenen Daten: Bei jedem Zugriff führt das DBMS die hinterlegte Abfrage auf den aktuellen Tabellen aus.

CREATE VIEW impfungen_je_art AS
SELECT t.tierart, s.bezeichnung, i.datum
FROM impfung i
INNER JOIN tier t      ON i.tier_id = t.tier_id
INNER JOIN impfstoff s ON i.impfstoff_id = s.impfstoff_id;

SELECT tierart, COUNT(*) AS anzahl
FROM impfungen_je_art
GROUP BY tierart;

Ergebnis: Hund 4, Kaninchen 1, Katze 1.

Sichten haben drei Vorteile:

  • Einfacher: Wer auswertet, muss die Verknüpfungen nicht kennen.
  • Sicherer: Eine Sicht zeigt nur ausgewählte Spalten und Zeilen. Wer nur die Sicht lesen darf, sieht die übrigen Daten nicht (Kapitel 8.4.4).
  • Stabiler: Ändert sich der Aufbau der Tabellen, passt du nur die Sicht an; Berichte, die sie nutzen, bleiben gleich.

Beispiel

Für die Praxisleitung soll eine Auswertung ohne Besitzerdaten entstehen (Datenminimierung, Kapitel 8.1.3). Die Auszubildende legt die Sicht impfungen_je_art an. Sie enthält Tierart, Impfstoff und Datum, aber keine Besitzerdaten wie Namen, Wohnorte oder Telefonnummern. Das Auswertungsprogramm der Praxisleitung bekommt nur Leserechte auf diese Sicht.

Häufiger Fehler

„Eine Sicht ist eine Kopie der Daten.“ Nein: Sie speichert nur die Abfrage. Ändert sich eine Impfung in der Tabelle, zeigt die Sicht beim nächsten Zugriff den neuen Stand.

Merksatz

  • Unterabfrage: ein SELECT in Klammern, dessen Ergebnis die äußere Abfrage als Wert (mit =, <, >) oder als Liste (mit IN, NOT IN) verwendet.
  • Sicht: gespeicherte Abfrage ohne eigene Daten; vereinfacht Auswertungen und zeigt nur ausgewählte Spalten und Zeilen.

8.3.5 Daten ändern und Transaktionen

Beim Prüfen der Datenqualität (Kapitel 8.1.4) ist eine Dublette aufgefallen: Frau Yilmaz steht in der zentralen Datenbank zweimal, als Nummer 2 aus der Praxissoftware des Stammhauses und als Nummer 9 vom Standort Nord. Unter Nummer 9 sind zwei ihrer Tiere eingetragen, die nicht zum Ausschnitt aus Kapitel 8.3.1 gehören. Du sollst die beiden Einträge zusammenführen. Dafür fügst du Daten ein, änderst und löschst sie und sorgst dafür, dass dabei nichts halb erledigt bleibt.

Einfügen, ändern, löschen#

INSERT INTO besitzer (besitzer_id, name, ort, telefon)
VALUES (9, 'Yilmaz', 'Halle', '0345 7654321');

UPDATE tier
SET besitzer_id = 2
WHERE besitzer_id = 9;

DELETE FROM besitzer
WHERE besitzer_id = 9;
  • INSERT INTO fügt eine Zeile ein. Die Werte stehen in derselben Reihenfolge wie die genannten Spalten. Nicht genannte Spalten bekommen ihren DEFAULT oder werden NULL; ist eine solche Spalte NOT NULL und hat keinen DEFAULT, lehnt das DBMS das Einfügen ab.
  • UPDATE … SET ändert Werte in allen Zeilen, die die WHERE-Bedingung erfüllen.
  • DELETE FROM löscht alle Zeilen, die die Bedingung erfüllen. Verweisen noch andere Zeilen darauf, lehnt das DBMS das Löschen ohne ON-DELETE-Regel ab (Kapitel 8.2.3).

Das INSERT oben zeigt, wie die Dublette beim Übernehmen entstanden ist. Zum Zusammenführen brauchst du nur das UPDATE und das DELETE.

Häufiger Fehler

„UPDATE tier SET besitzer_id = 2 ändert schon das Richtige.“ Ohne WHERE gelten UPDATE und DELETE für jede Zeile der Tabelle: Alle Tiere gehörten danach Frau Yilmaz. Prüfe die Bedingung vorher mit einem SELECT, das dieselbe WHERE-Bedingung hat.

Transaktionen#

Die beiden Schritte gehören zusammen. Bricht die Verbindung nach dem UPDATE ab, sind die Tiere schon umgehängt, der doppelte Eintrag aber noch da. Läuft das DELETE zuerst, scheitert es an den Tieren, die noch auf Nummer 9 verweisen. Damit mehrere Befehle nur gemeinsam wirken, fasst du sie zu einer Transaktion zusammen:

START TRANSACTION;
UPDATE tier SET besitzer_id = 2 WHERE besitzer_id = 9;
DELETE FROM besitzer WHERE besitzer_id = 9;
COMMIT;

COMMIT schreibt alle Änderungen der Transaktion endgültig fest. ROLLBACK macht sie alle rückgängig, etwa wenn ein Befehl einen Fehler meldet. Je nach System beginnt eine Transaktion mit START TRANSACTION oder BEGIN. Ohne ausdrücklich begonnene Transaktion schreiben viele Systeme jeden Befehl sofort fest (Autocommit).

Die ACID-Eigenschaften#

EigenschaftBedeutungIm Beispiel
Atomarität (Atomicity)alles oder nichtsentweder umgehängt und gelöscht oder beides nicht
Konsistenz (Consistency)nach der Transaktion gelten alle Regeln der Datenbankkein Tier verweist auf eine gelöschte Besitzerin

Beispiel

Die Auszubildende führt zuerst SELECT * FROM tier WHERE besitzer_id = 9 aus und sieht zwei Tiere. Dann startet sie die Transaktion. Das UPDATE meldet „2 Zeilen geändert“, das DELETE „1 Zeile gelöscht“. Beides passt zur Erwartung, also schließt sie mit COMMIT ab. Hätte das UPDATE 200 Zeilen gemeldet, hätte sie mit ROLLBACK abgebrochen.

Merksatz

INSERT fügt ein, UPDATE ändert und DELETE löscht, immer mit passender WHERE-Bedingung; eine Transaktion bündelt zusammengehörige Befehle, die mit COMMIT gemeinsam gelten oder mit ROLLBACK gemeinsam verworfen werden (ACID).
