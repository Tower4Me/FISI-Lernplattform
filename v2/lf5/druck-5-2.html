5.2Datenformate und Speicherung

AP1LF5: Software zur Verwaltung von Daten anpassen

5.2.1 Text- und Binärdateien

Die Tierarztpraxis hat Daten in vielen Formen: eine Tabelle, PDF-Befunde, Röntgenbilder, eine Exportdatei des Labors. Ob du eine Datei mit jedem Editor öffnen und weiterverarbeiten kannst oder ein bestimmtes Programm brauchst, hängt davon ab, ob sie als Text oder binär gespeichert ist.

Zwei Grundformen#

TextdateiBinärdatei
Inhaltnur Zeichen in einer Zeichenkodierung (deshalb auch „ASCII-Datei“ genannt), etwa ASCII oder UTF-8 (Kapitel 5.1.3)beliebige Bytes nach einem festgelegten Format
Öffnenmit jedem Texteditor lesbar und bearbeitbar, wenn die Zeichenkodierung stimmtnur mit einem Programm, das das Format kennt; im Editor erscheint Zeichensalat
Größeoft größer, Zahlen stehen als Ziffernfolgenoft kompakter, Zahlen stehen direkt als Bytes
Beispiele.txt, .csv, .json, .xml, .html, Quellcode.png, .jpg, .pdf, .exe, .docx, .xlsx, Datenbankdateien

Auch eine Zahl kann so oder so gespeichert sein: Als Text braucht 1250 vier Zeichen, also 4 Byte in ASCII. Binär als 16-Bit-Ganzzahl braucht sie 2 Byte. Dafür ist die Textform für Menschen lesbar und von jedem Programm verarbeitbar.

Moderne Office-Dateien wie .docx sind übrigens ZIP-Archive mit XML-Dateien darin: Der Inhalt ist größtenteils Text (Bilder liegen binär darin), die Datei als Ganzes ist binär. Deshalb beginnt sie wie jedes ZIP-Archiv mit den Zeichen PK.

Woran du ein Format erkennst#

  • Dateiendung: ein Hinweis, aber leicht änderbar und nicht verbindlich.
  • Dateisignatur: Viele Binärformate beginnen mit festen Bytes, etwa PDF mit %PDF, PNG mit den Bytes 89 50 4E 47 (hexadezimal, Kapitel 5.1.2). Programme erkennen das Format daran auch bei falscher Endung.
  • MIME-Typ: Im Web und bei E-Mail-Anhängen gibt eine Angabe wie application/pdf oder text/csv das Format an.
  • Base64: Wo nur Text übertragen werden darf, etwa im E-Mail-Anhang, wird eine Binärdatei in Textzeichen umkodiert. Sie wird dadurch rund ein Drittel größer.

Formate umwandeln#

Passt das Format der Quelle nicht zum Zielprogramm, gibt es mehrere Wege: die Exportfunktion der Quelle (etwa „Speichern unter CSV“), die Importfunktion des Ziels, einen Dateikonverter oder ein kleines eigenes Umwandlungsprogramm. Prüfe danach stichprobenartig, ob Umlaute, Datumsangaben und Kommazahlen richtig angekommen sind.

Beispiel

Das Laborgerät der Praxis speichert Messreihen in einem herstellereigenen Binärformat. Die neue Praxissoftware liest aber nur CSV. Der Auszubildende findet in der Gerätesoftware eine Exportfunktion „Messwerte als CSV“, richtet sie als tägliche Aufgabe ein und prüft, dass Dezimalzahlen wie 38,5 nicht als 385 ankommen.

Häufiger Fehler

„Ich benenne die Datei von .xlsx in .csv um, dann ist sie CSV.“ Nein: Die Endung ändert nicht den Inhalt. Die Datei bleibt ein Excel-Format; umwandeln muss sie ein Programm per Export.

Merksatz

  • Textdatei: nur Zeichen in einer Kodierung, mit jedem Editor lesbar; Binärdatei: beliebige Bytes, braucht ein passendes Programm, oft kompakter.
  • Format erkennen an Endung, Dateisignatur und MIME-Typ; umwandeln per Export, Import oder Konverter, danach Stichprobe.

5.2.2 Austauschformate: CSV, JSON, XML

Die Praxissoftware soll Termine an eine Online-Terminbuchung melden und Impfdaten aus der alten Tabelle übernehmen. Damit zwei Programme Daten austauschen können, brauchen sie ein gemeinsames Format. Drei Textformate decken die meisten Fälle ab: CSV, JSON und XML.

Tierdaten in drei Formaten#

tiername;tierart;geburtsdatum;gewicht_kg
Mimi;Katze;2021-05-14;4,35
Bello;Hund;2018-11-02;12,4

CSV (Comma-Separated Values): eine Zeile pro Datensatz, Werte durch ein Trennzeichen getrennt. In Deutschland ist das Semikolon üblich, weil das Komma als Dezimalzeichen dient. Die erste Zeile enthält oft die Spaltennamen. Enthält ein Wert selbst das Trennzeichen oder einen Zeilenumbruch, steht er in doppelten Anführungszeichen, etwa "Mimi; die Kleine". Der Standard RFC 4180 sieht eigentlich das Komma vor.

[
  {"tiername": "Mimi", "tierart": "Katze",
   "geburtsdatum": "2021-05-14", "gewicht_kg": 4.35,
   "impfungen": ["Katzenschnupfen", "Tollwut"]},
  {"tiername": "Bello", "tierart": "Hund",
   "geburtsdatum": "2018-11-02", "gewicht_kg": 12.4,
   "impfungen": ["Tollwut"]}
]

JSON (JavaScript Object Notation): Objekte in geschweiften Klammern mit Paaren aus Schlüssel und Wert, Listen in eckigen Klammern. Kennt Zahlen, Text, Wahrheitswerte und null; Daten lassen sich verschachteln. Zahlen stehen in JSON immer mit Dezimalpunkt (4.35). Einen eigenen Datumstyp gibt es nicht; ein Datum steht als Text, am besten nach ISO 8601.

<tiere>
  <tier art="Katze">
    <name>Mimi</name>
    <geburtsdatum>2021-05-14</geburtsdatum>
    <gewicht einheit="kg">4.35</gewicht>
  </tier>
</tiere>

XML (Extensible Markup Language): Daten zwischen öffnenden und schließenden Tags, zusätzliche Angaben als Attribute. Ein Schema kann genau festlegen, welche Elemente erlaubt sind.

Vergleich#

CSVJSONXML
Strukturflache Tabelleverschachteltverschachtelt, mit Attributen
Datentypenkeine, alles TextZahl, Text, Wahrheitswert, null, Liste, Objektalles Text, Typen über ein Schema
Größesehr kompaktkompaktausführlich durch Tags
Typischer EinsatzTabellenexport, Import in TabellenkalkulationWeb-Schnittstellen (APIs), KonfigurationDokumente, Behörden- und Branchenstandards, Office-Dateien

Alle drei sind Textformate. JSON und XML sind standardmäßig UTF-8; CSV-Dateien aus Excel sind oft noch Windows-1252 (Kapitel 5.1.3). Für einen reibungslosen Austausch müssen beide Seiten auch Details abstimmen: Trennzeichen, Dezimalzeichen, Datumsformat (am sichersten JJJJ-MM-TT nach ISO 8601) und Zeichenkodierung.

Beispiel

Die Online-Terminbuchung erwartet Termine als JSON über eine Web-Schnittstelle. Die Impfliste aus der alten Tabelle übernimmt die Auszubildende dagegen per CSV-Import: Sie speichert die Tabelle als CSV mit Semikolon und UTF-8, ordnet im Importdialog die Spalten den Feldern der Praxissoftware zu und prüft danach zehn zufällige Tiere.

Daten konvertieren#

Oft liegen Daten im falschen Format vor, etwa eine alte Tabelle, die in die Praxissoftware soll. Konvertiert wird über die Export- und Importfunktion der Programme oder mit einem Konverter. Dabei kann etwas verloren gehen: Formatierungen und Formeln fallen beim Export als CSV weg, verschachtelte Daten passen nicht in eine flache Tabelle, und eine falsche Zeichenkodierung zerstört Umlaute. Deshalb gilt: vorher eine Kopie des Originals sichern, danach eine Stichprobe mit dem Original vergleichen.

Häufiger Fehler

„CSV ist immer mit Komma getrennt.“ Nein: Trotz des Namens nutzen deutsche Programme meist das Semikolon. Stimmt das Trennzeichen nicht, landet beim Import eine ganze Zeile in einer einzigen Spalte.

Merksatz

  • CSV: flache Tabelle, Trennzeichen, kein Datentyp; JSON: Schlüssel-Wert-Paare und Listen, verschachtelt, Standard bei Web-Schnittstellen; XML: Tags und Attribute, ausführlich, Aufbau per Schema genau festlegbar.
  • Austausch abstimmen: Trennzeichen, Dezimalzeichen, Datumsformat, Zeichenkodierung.

5.2.3 Wo Daten gespeichert werden

Bisher liegt die Patiententabelle der Tierarztpraxis auf einem PC am Empfang. Fällt er aus, steht die Praxis still, und in den Behandlungsräumen sieht niemand die Daten. Wo Daten gespeichert werden, entscheidet über Verfügbarkeit, Schutz und Kosten. Deshalb wählst du die Speicherlösung nach den Anforderungen aus der Datenanalyse (Kapitel 5.1.1).

Speicherlösungen#

LösungStärkenSchwächenPasst für
Datei auf dem eigenen Rechnereinfach, keine laufenden Kostennur an einem Gerät, Ausfall trifft alle, keine gleichzeitige BearbeitungEinzelplatz, private Daten
Datei auf einem Netzlaufwerk (NAS, Server)von mehreren Arbeitsplätzen erreichbar, zentral sicherbargleichzeitiges Bearbeiten derselben Datei führt zu KonfliktenDokumente, Bilder, Austauschdateien
Datenbankviele gleichzeitig, Daten bleiben stimmig, schnelles Suchen und Auswerten, Rechte pro Feld oder Tabellebraucht Datenbanksystem und Pflegestrukturierte Daten in Mehrbenutzer-Anwendungen (Kapitel 5.3)
Cloud-Dienstvon überall erreichbar, Betrieb und Hardware beim Anbieter, wächst mitabhängig von Internet und Anbieter, laufende Kosten, Datenschutz vertraglich regelnverteilte Teams, Software als Dienst (SaaS)

Worauf du bei der Auswahl achtest#

  • Mehrbenutzerzugriff: Arbeiten mehrere Personen gleichzeitig mit denselben Daten, ist eine Datenbank fast immer besser als eine gemeinsame Datei.
  • Verfügbarkeit: Wie lange darf ein Ausfall dauern? Daraus folgen Sicherung, Ersatzgeräte oder ein Cloud-Dienst mit vertraglich zugesicherter Verfügbarkeit (Service Level Agreement, SLA).
  • Datenschutz: Wo stehen die Server, wer hat Zugriff? Verarbeitet ein Cloud-Dienst personenbezogene Daten, etwa die der Tierhalterinnen und Tierhalter, braucht es einen Vertrag zur Auftragsverarbeitung (Art. 28 DSGVO); ein Standort in der EU erleichtert die Prüfung.
  • Datensicherheit: Zugriffsrechte und Verschlüsselung schützen die Daten, und jede Lösung braucht eine Datensicherung, auch die Cloud. Löscht jemand Daten oder verschlüsselt Schadsoftware sie, wird die Änderung sonst sofort auf alle Geräte übertragen.
  • Speicheranforderung und Kosten: Menge heute und in einigen Jahren (LF2, Kapitel 2.4.2), Kauf gegenüber laufender Miete.

Vertiefung

Wie Datensicherungen geplant werden, wird in LF4, Kapitel 4.6.2 behandelt.

Beispiel

Für die Tierarztpraxis empfiehlt das Systemhaus eine Praxissoftware mit Datenbank auf einem kleinen Server im Praxisnetz: Empfang und beide Behandlungsräume arbeiten gleichzeitig, auch wenn das Internet ausfällt. Röntgenbilder liegen als Dateien auf dem NAS, verknüpft mit dem Patienten. Gesichert wird täglich verschlüsselt auf ein zweites Gerät und wöchentlich außer Haus. Eine reine Cloud-Lösung lehnt die Inhaberin ab, weil der Internetanschluss der Praxis oft gestört ist.

Häufiger Fehler

„In der Cloud brauche ich keine Datensicherung.“ Nein: Der Anbieter schützt vor seinen Hardwareausfällen, aber nicht vor versehentlichem Löschen, Schadsoftware oder einem gekündigten Konto. Eine eigene Sicherung bleibt nötig.

Merksatz

  • Speicherlösungen: lokale Datei, Netzlaufwerk, Datenbank, Cloud; Mehrbenutzer-Anwendungen mit strukturierten Daten brauchen eine Datenbank.
  • Auswahl nach Mehrbenutzerzugriff, Verfügbarkeit, Datenschutz, Datensicherheit, Speichermenge und Kosten; gesichert wird immer.

5.2.4 Daten komprimieren und prüfen

Röntgenbilder füllen schnell jede Festplatte, und beim Übertragen soll kein Bit verloren gehen. Kompression spart Platz und Übertragungszeit, Prüfverfahren zeigen, ob Daten unverändert angekommen sind. Beides steckt in fast jedem Dateiformat und jeder Übertragung.

Kompression#

VerlustfreiVerlustbehaftet
PrinzipWiederholungen und Muster kürzer schreiben; beim Entpacken entsteht exakt das OriginalDetails weglassen, die Menschen kaum wahrnehmen; das Original lässt sich nicht wiederherstellen

Wie stark komprimiert wird, beschreibt die Kompressionsrate: etwa „10 : 1“, wenn eine Datei auf ein Zehntel schrumpft, also 90 % Platz spart (aus 50 MB werden 5 MB). Text komprimiert sich gut; bereits komprimierte Dateien wie JPEG oder MP4 werden durch ein ZIP-Archiv kaum kleiner.

Daten prüfen#

Bei Speicherung und Übertragung können einzelne Bits kippen, oder Daten werden absichtlich verändert. Prüfverfahren hängen deshalb einen aus den Daten berechneten Wert an. Der Empfänger rechnet nach und vergleicht.

VerfahrenFunktionsweiseEinsatz
Paritätsbitein zusätzliches Bit macht die Zahl der Einsen gerade (oder ungerade); erkennt ein gekipptes Bit, aber nicht zwei; korrigieren kann es nichteinfache serielle Übertragungen, früher Speicherbausteine
Prüfziffereine aus den übrigen Ziffern berechnete Ziffer erkennt die meisten Tippfehler und ZahlendreherIBAN, EAN-Strichcode, ISBN
Prüfsumme (CRC)ein aus allen Bytes berechneter Wert erkennt zufällige ÜbertragungsfehlerEthernet-Rahmen (FCS), ZIP-Dateien, Datenträger
Hashwertein „Fingerabdruck“ der Daten; mit einem Vergleichswert aus vertrauenswürdiger Quelle fallen auch absichtliche Änderungen aufDownloads prüfen, Integrität nachweisen

Beispiel EAN-13: Die ersten 12 Ziffern 4 0 0 6 3 8 1 3 3 3 9 3 werden abwechselnd mal 1 und mal 3 genommen und addiert: 89. Die Prüfziffer ergänzt auf den nächsten Zehner: 90 − 89 = 1. Die vollständige Nummer lautet 4006381333931. Die IBAN hat dagegen zwei Prüfziffern (Stelle 3 und 4).

Paritätsbit, Prüfziffer und CRC erkennen Fehler, schützen aber nicht vor Manipulation: Wer Daten absichtlich ändert, kann den Prüfwert einfach neu berechnen.

Vertiefung

Wie Hashwerte und digitale Signaturen gegen Manipulation schützen, wird in LF4, Kapitel 4.5.5 behandelt.

Häufiger Fehler

„Ein JPEG-Bild wird noch einmal kleiner, wenn ich es zippe.“ Kaum: JPEG ist bereits komprimiert. Ein ZIP-Archiv spart dann fast nichts; bei Text oder Tabellen dagegen viel.

Merksatz

  • Kompression: verlustfrei (ZIP, PNG) stellt das Original wieder her, verlustbehaftet (JPEG, MP3, H.264) lässt Details weg.
  • Prüfen: Paritätsbit, Prüfziffer und CRC erkennen Fehler; gegen absichtliche Änderung helfen Hashwerte aus vertrauenswürdiger Quelle und digitale Signaturen.
