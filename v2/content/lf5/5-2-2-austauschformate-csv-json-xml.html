Die Praxissoftware soll Termine an eine Online-Terminbuchung melden und Impfdaten aus der alten Tabelle übernehmen. Damit zwei Programme Daten austauschen können, brauchen sie ein gemeinsames Format. Drei Textformate decken die meisten Fälle ab: CSV, JSON und XML.

Tierdaten in drei Formaten

tiername;tierart;geburtsdatum;gewicht_kg
Mimi;Katze;2021-05-14;4,35
Bello;Hund;2018-11-02;12,4

CSV (Comma-Separated Values): eine Zeile pro Datensatz, Werte durch ein Trennzeichen getrennt. In Deutschland ist das Semikolon üblich, weil das Komma als Dezimalzeichen dient. Die erste Zeile enthält oft die Spaltennamen. Enthält ein Wert selbst das Trennzeichen oder einen Zeilenumbruch, steht er in doppelten Anführungszeichen, etwa "Mimi; die Kleine". Der Standard RFC 4180 sieht eigentlich das Komma vor.

[
  {"tiername": "Mimi", "tierart": "Katze",
   "geburtsdatum": "2021-05-14", "gewicht_kg": 4.35,
   "impfungen": ["Katzenschnupfen", "Tollwut"]},
  {"tiername": "Bello", "tierart": "Hund",
   "geburtsdatum": "2018-11-02", "gewicht_kg": 12.4,
   "impfungen": ["Tollwut"]}
]

JSON (JavaScript Object Notation): Objekte in geschweiften Klammern mit Paaren aus Schlüssel und Wert, Listen in eckigen Klammern. Kennt Zahlen, Text, Wahrheitswerte und null; Daten lassen sich verschachteln. Zahlen stehen in JSON immer mit Dezimalpunkt (4.35). Einen eigenen Datumstyp gibt es nicht; ein Datum steht als Text, am besten nach ISO 8601.

<tiere>
  <tier art="Katze">
    <name>Mimi</name>
    <geburtsdatum>2021-05-14</geburtsdatum>
    <gewicht einheit="kg">4.35</gewicht>
  </tier>
</tiere>

XML (Extensible Markup Language): Daten zwischen öffnenden und schließenden Tags, zusätzliche Angaben als Attribute. Ein Schema kann genau festlegen, welche Elemente erlaubt sind.

Alle drei sind Textformate. JSON und XML sind standardmäßig UTF-8; CSV-Dateien aus Excel sind oft noch Windows-1252 (Kapitel 5.1.3). Für einen reibungslosen Austausch müssen beide Seiten auch Details abstimmen: Trennzeichen, Dezimalzeichen, Datumsformat (am sichersten JJJJ-MM-TT nach ISO 8601) und Zeichenkodierung.

Beispiel

Die Online-Terminbuchung erwartet Termine als JSON über eine Web-Schnittstelle. Die Impfliste aus der alten Tabelle übernimmt die Auszubildende dagegen per CSV-Import: Sie speichert die Tabelle als CSV mit Semikolon und UTF-8, ordnet im Importdialog die Spalten den Feldern der Praxissoftware zu und prüft danach zehn zufällige Tiere.

„CSV ist immer mit Komma getrennt.“ Nein: Trotz des Namens nutzen deutsche Programme meist das Semikolon. Stimmt das Trennzeichen nicht, landet beim Import eine ganze Zeile in einer einzigen Spalte.

  • CSV: flache Tabelle, Trennzeichen, kein Datentyp; JSON: Schlüssel-Wert-Paare und Listen, verschachtelt, Standard bei Web-Schnittstellen; XML: Tags und Attribute, ausführlich, Aufbau per Schema genau festlegbar.
  • Austausch abstimmen: Trennzeichen, Dezimalzeichen, Datumsformat, Zeichenkodierung.
