Der Verbund hat eine Website für Tierhalter, und die Web-API der Termin-App läuft im Stammhaus (Kapitel 9.4.4). Später sollen weitere Dienste von außen erreichbar werden. Port 443 der einen öffentlichen Adresse kann der Router aber nur an ein einziges internes Ziel weiterleiten. Deshalb stellt das Systemhaus einen einzigen Eingang davor: einen Reverse Proxy.

Webserver und Hosting

Ein Webserver (etwa Apache, nginx, IIS) nimmt HTTP-Anfragen an, auf Port 80 oder mit HTTPS auf Port 443 (Ports und URL: LF3, Kapitel 3.5.5), und liefert Dateien oder die Ausgabe einer Anwendung zurück. Wichtige Einstellungen:

  • Virtuelle Hosts: Ein Server bedient mehrere Domains; er unterscheidet sie am Namen in der Anfrage (Host-Kopfzeile, bei HTTPS schon beim Verbindungsaufbau).
  • Standarddokument: Datei, die beim Aufruf eines Verzeichnisses geliefert wird, meist index.html. Fehlt sie und ist das Auflisten des Verzeichnisses verboten, antwortet der Server mit 403 (Forbidden).
  • Zertifikat für HTTPS, ausgestellt auf den Namen, unter dem die Seite aufgerufen wird.

Wo die Website läuft, ist eine Frage interner und externer Ressourcen (Kapitel 9.1.4): auf einem Server, den sich viele Kunden des Anbieters teilen (Shared Hosting), auf einem gemieteten Server, in der Cloud oder auf einem eigenen Server. Eine reine Informationsseite liegt meist günstiger und sicherer beim Anbieter als im eigenen Haus.

Reverse Proxy

Ein Reverse Proxy steht vor einem oder mehreren internen Servern und nimmt alle Anfragen aus dem Internet stellvertretend an. Er leitet sie an den passenden Server weiter und gibt dessen Antwort zurück. Der Client sieht nur den Proxy.

  • Ein Eingang: Nur der Proxy braucht eine Weiterleitung im Router. Nach Name oder Pfad verteilt er auf die Server dahinter.
  • TLS an einer Stelle: Der Proxy hält die Zertifikate und entschlüsselt; die Server dahinter müssen das nicht selbst erledigen.
  • Lastverteilung: Er kann Anfragen auf mehrere gleiche Server verteilen und einen ausgefallenen überspringen.
  • Zwischenspeicher: Häufig abgerufene Inhalte liefert er selbst aus.
  • Schutz: Interne Adressen und Server bleiben verborgen; der Proxy kann auffällige Anfragen filtern.

Beispiel

Das Systemhaus stellt den Reverse Proxy 10.10.0.149 in das Server-VLAN und ändert die Weiterleitung im Router: 198.51.100.10:443 geht jetzt an den Proxy statt direkt an den API-Server. In der öffentlichen Zone beim Anbieter zeigt termine.praxisverbund.example auf 198.51.100.10. Der Proxy hält das Zertifikat für diesen Namen und gibt Anfragen an den Pfad /api/ an 10.10.0.148 weiter. Kommt später ein zweiter Dienst dazu, ergänzt die Auszubildende nur eine Regel im Proxy; der Router bleibt unverändert.

„Ein Reverse Proxy schützt die Mitarbeitenden beim Surfen.“ Das leistet ein Forward Proxy. Der Reverse Proxy steht auf der anderen Seite und vertritt Server gegenüber Anfragen aus dem Internet.

  • Webserver: HTTP(S) auf 80/443, virtuelle Hosts, Standarddokument (fehlt es und ist das Auflisten verboten, 403), Zertifikat auf den Aufrufnamen.
  • Reverse Proxy: ein Eingang vor internen Servern mit TLS, Lastverteilung, Zwischenspeicher und verborgener Struktur; der Forward Proxy steht vor den Clients.
