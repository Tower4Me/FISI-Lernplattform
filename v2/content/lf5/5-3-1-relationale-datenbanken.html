In der alten Tabelle der Tierarztpraxis steht die Anschrift einer Besitzerin bei jedem ihrer Tiere. Zieht sie um, wird die Adresse an einer Stelle geändert und an den anderen vergessen. Eine relationale Datenbank verhindert solche Widersprüche, indem jede Angabe nur einmal gespeichert und über Schlüssel verknüpft wird.

Datenbank und Datenbanksystem

Eine Datenbank ist eine geordnete, dauerhaft gespeicherte Sammlung zusammengehöriger Daten. Verwaltet wird sie von einem Datenbankmanagementsystem (DBMS), etwa MariaDB, PostgreSQL oder Microsoft SQL Server. Das DBMS sorgt dafür, dass mehrere Personen gleichzeitig arbeiten können, dass Regeln eingehalten werden, dass nur Berechtigte zugreifen und dass die Daten nach einem Absturz wieder in einem stimmigen Zustand sind.

Tabellen, Datensätze, Attribute

In einer relationalen Datenbank liegen die Daten in Tabellen (Relationen). Jede Zeile ist ein Datensatz, jede Spalte ein Attribut mit festem Datentyp (Kapitel 5.1.4).

Schlüssel

  • Primärschlüssel (PK): ein Attribut oder eine Kombination, die jeden Datensatz einer Tabelle eindeutig kennzeichnet, hier besitzer_id und tier_id. Er darf nicht leer sein und sich nicht wiederholen. Oft ist es eine fortlaufende Nummer ohne weitere Bedeutung.
  • Fremdschlüssel (FK): ein Attribut, das auf den Primärschlüssel einer anderen Tabelle verweist, hier besitzer_id in der Tabelle Tier. Er verknüpft die Tabellen: Mimi und Bello gehören zu Weber.

Das DBMS kann prüfen, dass jeder Fremdschlüssel auf einen vorhandenen Datensatz zeigt (referenzielle Integrität). Dann lässt sich kein Tier mit einer Besitzernummer anlegen, die es nicht gibt, und eine Besitzerin, auf die noch Tiere verweisen, nicht einfach löschen.

Warum aufteilen

Stünde alles in einer einzigen Tabelle, würden die Besitzerdaten für jedes Tier wiederholt. Diese Redundanz kostet Platz und führt zu Anomalien:

  • Änderungsanomalie: Die Adresse wird nur an einer von mehreren Stellen geändert, die Daten widersprechen sich.
  • Einfügeanomalie: Eine neue Besitzerin lässt sich erst speichern, wenn sie ein Tier hat.
  • Löschanomalie: Wird das letzte Tier gelöscht, verschwinden auch die Daten der Besitzerin.

Getrennte Tabellen, die über Schlüssel verknüpft sind, speichern jede Angabe nur einmal. Wer die Daten braucht, fügt sie bei der Abfrage wieder zusammen.

Wie du Tabellen schrittweise in Normalformen bringt und mit SQL abfragt, wird in LF8 behandelt.

Beispiel

Frau Weber zieht von Leipzig nach Markkleeberg. In der Datenbank ändert die Auszubildende einen einzigen Datensatz in der Tabelle Besitzer. Mimi und Bello verweisen über besitzer_id = 1 automatisch auf die neue Anschrift.

„Der Name ist doch eindeutig genug als Primärschlüssel.“ Nein: Namen wiederholen sich und können sich ändern. Ein Primärschlüssel muss eindeutig und stabil sein; deshalb nimmst du meist eine eigene Nummer.

  • Relationale Datenbank: Tabellen mit Datensätzen (Zeilen) und Attributen (Spalten), verwaltet von einem DBMS.
  • Primärschlüssel kennzeichnet jeden Datensatz eindeutig, Fremdschlüssel verweist auf den Primärschlüssel einer anderen Tabelle; Aufteilen vermeidet Redundanz und Anomalien.
