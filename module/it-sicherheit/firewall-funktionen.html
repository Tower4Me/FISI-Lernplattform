Firewall-Funktionen AP1 AP2

Einstieg

Vor einem Club kann die Einlasskontrolle unterschiedlich gründlich sein. Der einfachste Türsteher schaut nur auf die Gästeliste: Name drauf, rein. Ein aufmerksamerer merkt sich zusätzlich, wer schon drin war und nur kurz zum Rauchen draußen ist. Ein dritter schaut in jede Tasche, bevor jemand durchgeht. Und manchmal geht gar kein Gast selbst hinein, sondern ein Bote holt die Bestellung und bringt sie heraus. Genau diese Stufen gibt es auch bei einer Firewall: Je tiefer sie in den Datenverkehr hineinschaut, desto mehr Angriffe erkennt sie, desto mehr Rechenleistung braucht sie aber auch.

Konzept

Eine Firewall kontrolliert den Datenverkehr zwischen Netzen anhand von Regeln. Sie ist die wichtigste Grenze zwischen „innen“ (vertrauenswürdig) und „außen“ (Internet). Es gibt verschiedene Ausbaustufen:

TypArbeitet aufErkennt
PaketfilterSchicht 3/4 (IP, Port)Quelle, Ziel, Port, Protokoll
Stateful Inspection (SPI)Schicht 3/4 + VerbindungszustandGehört das Paket zu einer bestehenden Verbindung?
Application Level Gateway (ALG) / ProxySchicht 7Befehle und Inhalte eines bestimmten Anwendungsprotokolls
Application Firewall / NGFW / WAFbis Schicht 7Anwendung, Inhalt, Deep Packet Inspection

Paketfilter und Stateful Inspection

Ein Paketfilter betrachtet jedes Paket einzeln und vergleicht nur die Kopfdaten mit seiner Regelliste: Quell- und Ziel-IP, Quell- und Zielport, Protokoll. Er weiß nicht, ob ein eingehendes Paket die Antwort auf eine Anfrage von innen ist. Für Antworten müssten deshalb pauschal ganze Portbereiche geöffnet werden.

Stateful Packet Inspection (SPI) führt zusätzlich eine Zustandstabelle über alle aktiven Verbindungen. Baut ein Client von innen eine Verbindung auf, trägt die Firewall sie ein und lässt nur die passenden Antwortpakete wieder herein. Ein Paket von außen, das zu keiner bekannten Verbindung gehört, wird verworfen. SPI ist heute der Standard jeder Firewall.

Application Level Gateway (ALG) und Proxy

Ein Application Level Gateway arbeitet auf Schicht 7 und versteht ein bestimmtes Anwendungsprotokoll, zum Beispiel HTTP, SMTP oder FTP. Es gibt keine direkte Verbindung zwischen Client und Server: Das ALG nimmt die Verbindung selbst an, prüft die Befehle und Inhalte und baut eine eigene, neue Verbindung zum Ziel auf. Ein ALG arbeitet damit als Proxy. Nicht erlaubte Befehle (z. B. ein Datei-Upload per FTP) kann es gezielt sperren, auch wenn der Port an sich offen ist.

Man unterscheidet zwei Einsatzrichtungen eines Proxys:

TypSitzt auf Seite vonTypischer Einsatz
Forward-Proxy Client Internetzugriff der Clients filtern, protokollieren oder den Nutzer gegenüber dem Zielserver anonymisieren
Reverse-Proxy Server Lastverteilung auf mehrere Backend-Server, verbirgt die interne Serverstruktur vor dem Internet

Abgrenzung zur Firewall: Ein Proxy arbeitet auf Anwendungsebene und leitet Verbindungen im Namen des Clients bzw. Servers aktiv weiter – er ist selbst Kommunikationspartner für beide Seiten. Eine Firewall dagegen filtert primär nach Regeln auf Paket-/Portebene und lässt Verbindungen entweder durch oder blockiert sie, ohne selbst als aktiver Kommunikationspartner aufzutreten.

Deep Packet Inspection (DPI)

Deep Packet Inspection untersucht nicht nur die Kopfdaten, sondern auch die Nutzdaten eines Pakets. So erkennt die Firewall, welche Anwendung tatsächlich über einen Port spricht (z. B. ein Filesharing-Programm, das sich hinter Port 443 versteckt) oder ob im Inhalt ein bekanntes Angriffsmuster steckt. Verschlüsselter Verkehr (HTTPS) lässt sich nur prüfen, wenn die Firewall ihn aufbricht (TLS-Inspection) – das kostet Rechenleistung und muss datenschutzrechtlich geregelt sein.

Next-Generation-Firewall (NGFW)

Eine Next-Generation-Firewall (NGFW) macht Stateful Inspection, kann aber zusätzlich Application Control und Deep Packet Inspection bis Schicht 7 – eine reine Paketfilter-Regel („Port 443 erlauben“) ist nur die unterste Ausbaustufe. Eine WAF (Web Application Firewall) ist eine auf Webanwendungen spezialisierte Variante davon.

Typische Zusatzfunktionen einer NGFW sind Regeln pro Benutzer oder Gruppe statt nur pro IP-Adresse, ein integriertes IPS sowie URL-Filter. Wie ein IPS Angriffe erkennt, behandelt die Einheit IDS/IPS; wie Firewalls zu einer DMZ angeordnet werden, die Einheit Firewall-Architekturen & DMZ.

Praxisbeispiel

Die „Baumann IT-Systemhaus GmbH“ soll für einen Kunden mit eigenem Webshop entscheiden, welche Firewall-Funktionen nötig sind:

  • Eine Paketfilter-Regel „TCP 443 zum Webshop-Server erlauben“ lässt Kunden aus dem Internet auf den Shop zugreifen.
  • Damit die Mitarbeiter im Internet surfen können, ohne dass eingehend große Portbereiche offen stehen, nutzt die Firewall Stateful Inspection: Nur Antworten auf Verbindungen, die von innen aufgebaut wurden, kommen herein.
  • Ein Angreifer schickt eine SQL-Injection über ganz normales HTTPS an Port 443. Paketfilter und SPI sehen nur eine erlaubte Verbindung und lassen sie durch.
  • Eine reine Paketfilter-Regel würde nur Quelle/Ziel/Port prüfen; die eingesetzte NGFW erkennt zusätzlich, ob der Datenverkehr zur Anwendung „Webshop“ überhaupt plausibel aussieht (Deep Packet Inspection).
  • Den Internetzugriff der Mitarbeiter leitet die Firma über einen Forward-Proxy, der bekannte Schadseiten sperrt und Zugriffe protokolliert.

Merksatz

Firewall-Ausbaustufen: Paketfilter (L3/L4) → Stateful Inspection (+ Verbindungszustand) → NGFW/WAF (bis L7). Ein ALG/Proxy prüft ein Anwendungsprotokoll und baut als Stellvertreter eine eigene Verbindung auf; Deep Packet Inspection schaut in die Nutzdaten.
