Dynamische vs. statische Webseiten AP1

Einstieg

Eine statische Webseite ist wie ein vorgedruckter Flyer: Er wurde einmal gedruckt und ist danach für jeden Leser identisch, egal wer ihn in die Hand nimmt. Eine dynamische Webseite ist wie ein Kellner, der jede Bestellung individuell zusammenstellt — je nachdem, wer fragt und was gerade auf Lager ist, sieht das Ergebnis jedes Mal anders aus.

Konzept

Statisch vs. dynamisch

Eine statische Webseite besteht aus fertigen HTML-/CSS-/JS-Dateien, die auf dem Server unverändert liegen und bei jeder Anfrage identisch ausgeliefert werden — es findet keine serverseitige Berechnung des Inhalts statt. Eine dynamische Webseite erzeugt ihren Inhalt dagegen bei jeder Anfrage (zumindest teilweise) neu, z. B. aus einer Datenbank oder abhängig vom anfragenden Nutzer.

Client- vs. Serverseite

Dynamische Erzeugung kann an zwei Stellen passieren:

  • Serverseitig (Server-Side Rendering, SSR): der Server berechnet das fertige HTML, bevor es an den Browser gesendet wird (z. B. mit PHP, Node.js, Python/Django).
  • Clientseitig: der Browser lädt ein Grundgerüst plus JavaScript und baut die eigentliche Seite selbst zusammen, oft über Nachladen von Daten via API (z. B. mit React, Vue, Angular).

Vor- und Nachteile im Vergleich

KriteriumStatischDynamisch
Performance sehr schnell, da Dateien direkt ausgeliefert werden langsamer, da der Server bei jeder Anfrage rechnet
Caching vollständig cachebar, ideal für ein CDN aufwändiger, oft nur teilweise cachebar
Wartung Änderungen erfordern einen neuen Build/Upload Inhalt änderbar ohne Neu-Deployment (z. B. über ein CMS)
Sicherheit kleine Angriffsfläche, kein ausführbarer Servercode größere Angriffsfläche (z. B. SQL-Injection), da der Server aktiv Code ausführt und mit einer Datenbank interagiert

Bezug zu den Hosting-Anforderungen

Statische Seiten benötigen nur einen einfachen Webserver oder Static-Hosting-Dienst (siehe Einheit „Website-Aufruf & virtuelle Hosts“), der Dateien ausliefert. Dynamische Seiten brauchen zusätzlich eine Laufzeitumgebung auf dem Server (z. B. eine PHP-/Node.js-Umgebung) und häufig eine angebundene Datenbank.

Praxisbeispiel

Die TechNord GmbH betreibt zwei unterschiedliche Webauftritte:

  • Firmenwebsite (Leistungen, Über uns, Kontakt, Impressum): Der Inhalt ändert sich selten und ist für alle Besucher gleich — sie wird als statische Seite gebaut. Vorteil: schnelles Laden, günstiges Hosting, kaum Wartungsaufwand.
  • Kundenportal (Login, individuelle Bestellhistorie, Rechnungen): Der Inhalt ist für jeden Kunden unterschiedlich und muss aktuell aus der Datenbank stammen — sie läuft als dynamische, serverseitig generierte Anwendung mit Datenbankanbindung.

Merksatz

Statische Seiten liefern fertige Dateien unverändert aus (schnell, cachebar, wartungsarm bei seltenen Änderungen). Dynamische Seiten erzeugen den Inhalt bei jeder Anfrage neu — serverseitig (SSR, vor dem Senden) oder clientseitig (im Browser via JavaScript) — und brauchen dafür eine Laufzeitumgebung statt eines einfachen Datei-Servers.
