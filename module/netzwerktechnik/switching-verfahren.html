Switching-Verfahren (Store-and-Forward, Cut-Through, Fragment-Free) AP2

Einstieg

Stell dir eine Poststelle vor, die Pakete sortiert und weiterleitet. Ein besonders gründlicher Sachbearbeiter wartet, bis das komplette Paket angekommen ist, prüft es auf Beschädigungen und schickt es erst dann weiter — sicher, aber langsam. Ein schneller Kurier dagegen liest nur das Adressetikett, sobald es sichtbar ist, und reicht das Paket sofort weiter, ohne auf den Rest zu warten oder es zu prüfen — schnell, aber riskant, falls das Paket beschädigt ist. Ein Kompromiss-Sachbearbeiter wartet wenigstens, bis die ersten paar Zentimeter des Pakets durch seine Hände gelaufen sind (grobe Transportschäden zeigen sich meist gleich am Anfang), bevor er weiterreicht. Genau diese drei Strategien nutzt ein Switch, um ankommende Frames zu verarbeiten.

Konzept

MAC-Adresstabelle (CAM-Tabelle)

Damit ein Switch Frames gezielt nur an den richtigen Port weiterleiten kann (siehe Netzwerkkomponenten), braucht er eine Zuordnung, welche MAC-Adresse an welchem Port hängt. Diese MAC-Adresstabelle (auch CAM-Tabelle, Content Addressable Memory) liegt im Speicher des Switches und wird durch Backward Learning automatisch aufgebaut: Bei jedem eingehenden Frame merkt sich der Switch die Quell-MAC-Adresse zusammen mit dem Port, über den der Frame hereinkam.

  • Ist die Ziel-MAC-Adresse eines Frames noch nicht in der Tabelle bekannt, flutet der Switch den Frame an alle Ports außer dem Eingangsport — wie ein Hub, aber nur so lange, bis die Adresse gelernt wurde.
  • Einträge verfallen nach einer gewissen Zeit ohne weiteren Datenverkehr von dieser MAC-Adresse (Aging Time, häufig ca. 300 Sekunden) — das verhindert veraltete Einträge, z. B. wenn ein Gerät an einen anderen Port umgesteckt wurde.

Pufferspeicher-Architektur: Shared Memory vs. Port-based Memory

Davon zu unterscheiden ist eine zweite Speicherfrage: Wo legt der Switch Frames ab, während er auf einen freien Ausgangsport wartet oder — bei Store-and-Forward — den kompletten Frame puffert?

ArchitekturSpeicherzuordnungVor-/Nachteil
Port-based Memory (Port-Buffered Memory) jeder Port hat seinen eigenen, festen Pufferspeicher einfach und vorhersehbar, aber ineffizient: Ein einzelner Port-Puffer kann überlaufen (Frames werden verworfen), obwohl an anderen Ports noch reichlich freier Speicher vorhanden wäre
Shared Memory ein gemeinsamer Speicherpool für alle Ports, dynamisch zugewiesen nutzt den vorhandenen Speicher effizienter und verkraftet ungleichmäßige Lastspitzen besser, benötigt dafür aber mehr Steuerungsaufwand (Speicherverwaltung)

Diese Speicherarchitektur ist unabhängig von den drei Switching-Verfahren weiter unten: Sie beantwortet, wo ein Frame zwischengespeichert wird, während Store-and-Forward, Cut-Through und Fragment-Free beantworten, wann die Weiterleitung beginnt.

Die drei Switching-Verfahren

Unabhängig von der MAC-Adresstabelle stellt sich eine zweite Frage: Wann genau beginnt der Switch, einen bereits empfangenen Frame weiterzuleiten? Dafür gibt es drei Verfahren:

VerfahrenWeiterleitung abFehlerprüfungLatenz
Store-and-Forward vollständig empfangenem Frame ja — FCS/CRC-Prüfung, fehlerhafte Frames werden verworfen am höchsten
Cut-Through (auch: Fast Forward) gelesener Ziel-MAC-Adresse (nach den ersten 6 Byte des Frames) keine — fehlerhafte Frames werden ggf. mitweitergeleitet am niedrigsten
Fragment-Free (auch: Modified Cut-Through) empfangenen ersten 64 Byte teilweise — erkennt Kollisionsfragmente, keine vollständige CRC-Prüfung Kompromiss

Die 64-Byte-Grenze bei Fragment-Free ist kein Zufall: Sie entspricht genau der Mindestgröße eines gültigen Ethernet-Frames (siehe Protokoll-Header im Überblick). Kollisionsfragmente — sogenannte Runts — entstehen fast immer innerhalb dieser ersten 64 Byte. Fragment-Free wartet also gerade so lange, dass die häufigste Fehlerquelle zuverlässig erkannt wird, ohne wie Store-and-Forward auf den kompletten Frame warten zu müssen.

Store-and-Forward ist heute das mit Abstand gebräuchlichste Verfahren in modernen Switches — der Geschwindigkeitsvorteil von Cut-Through fällt bei den hohen Bandbreiten aktueller Netze kaum noch ins Gewicht, während die Fehlerprüfung verhindert, dass beschädigte Frames unnötig Bandbreite auf nachgelagerten Segmenten verbrauchen.

Praxisbeispiel

Ein IT-Systemhaus konfiguriert Switches für zwei unterschiedliche Szenarien bei einem Kunden.

  • Im Serverraum verbindet ein Switch mehrere Backup-Server über kurze, hochwertige Kabelstrecken mit sehr wenigen Übertragungsfehlern. Hier zählt die niedrige Latenz mehr als die Fehlerprüfung — der Switch wird auf Cut-Through konfiguriert.
  • An der Netzwerkgrenze zu einem alten Gebäudeteil mit teils noch ungeschirmter, älterer Verkabelung treten gelegentlich Störungen auf. Hier wählt der Techniker Store-and-Forward, damit beschädigte Frames zuverlässig erkannt und verworfen werden, statt sie unnötig weiter ins Netz zu leiten.
  • Ein älterer Switch, der zwischen beiden Welten vermitteln muss, läuft im Fragment-Free-Modus — ein Kompromiss, der zumindest Kollisionsfragmente zuverlässig abfängt, ohne die volle Store-and-Forward-Latenz in Kauf zu nehmen.

Typische Prüfungsfrage: „Warum wartet Fragment-Free genau auf die ersten 64 Byte eines Frames, bevor weitergeleitet wird?“ – Antwort: 64 Byte ist die Mindestgröße eines gültigen Ethernet-Frames. Kollisionsfragmente (Runts) entstehen fast immer innerhalb dieser ersten 64 Byte — Fragment-Free kann sie damit zuverlässig erkennen, ohne wie Store-and-Forward auf den kompletten Frame warten zu müssen.

Merksatz

MAC-Adresstabelle (CAM) wird durch Backward Learning aufgebaut, unbekannte Ziele werden geflutet. Store-and-Forward = ganzer Frame + CRC-Prüfung = sicher, aber langsam. Cut-Through = nur Ziel-MAC gelesen = schnell, aber ungeprüft. Fragment-Free = erste 64 Byte = Kompromiss, erkennt Kollisionsfragmente (Runts).
