Das Tabellenmodell steht. Jetzt legst du die Tabellen in der zentralen Datenbank an. Dafür schreibst du SQL-Befehle, statt dich durch eine Oberfläche zu klicken. Die Befehle lassen sich speichern, prüfen und auf dem Test- und dem echten Server gleich ausführen.

Die Teile von SQL

SQL (Structured Query Language) ist die Standardsprache relationaler Datenbanken. Ihre Befehle werden in Gruppen eingeteilt:

GruppeZweckBefehle
DDL (Data Definition Language)Struktur festlegenCREATE, ALTER, DROP
DML (Data Manipulation Language)Daten einfügen, ändern, löschenINSERT, UPDATE, DELETE
DQL (Data Query Language)Daten abfragenSELECT
DCL (Data Control Language)Rechte vergebenGRANT, REVOKE

Manche Lehrbücher zählen SELECT zur DML. Groß- und Kleinschreibung der Befehlswörter ist egal; üblich ist, sie groß zu schreiben. Ein Befehl endet mit einem Semikolon.

Tabellen anlegen

CREATE TABLE besitzer (
  besitzer_id INTEGER PRIMARY KEY,
  name        VARCHAR(60) NOT NULL,
  ort         VARCHAR(40),
  telefon     VARCHAR(20)
);

CREATE TABLE tier (
  tier_id      INTEGER PRIMARY KEY,
  name         VARCHAR(50) NOT NULL,
  tierart      VARCHAR(20) NOT NULL,
  geburtsdatum DATE,
  gewicht_kg   DECIMAL(5,2) CHECK (gewicht_kg > 0),
  besitzer_id  INTEGER NOT NULL,
  FOREIGN KEY (besitzer_id) REFERENCES besitzer (besitzer_id)
);

CREATE TABLE impfstoff (
  impfstoff_id INTEGER PRIMARY KEY,
  bezeichnung  VARCHAR(60) NOT NULL,
  hersteller   VARCHAR(60)
);

CREATE TABLE impfung (
  tier_id      INTEGER,
  impfstoff_id INTEGER,
  datum        DATE,
  charge       VARCHAR(20),
  PRIMARY KEY (tier_id, impfstoff_id, datum),
  FOREIGN KEY (tier_id) REFERENCES tier (tier_id),
  FOREIGN KEY (impfstoff_id) REFERENCES impfstoff (impfstoff_id)
);

Je Spalte stehen Name, Datentyp und Constraints (Kapitel 8.2.1). Ein Primärschlüssel aus einer Spalte kann direkt hinter ihr stehen; ein zusammengesetzter Schlüssel steht als eigene Angabe PRIMARY KEY (…), üblicherweise am Ende. Die Tabelle impfstoff legst du vor impfung an, denn ein Fremdschlüssel kann nur auf eine Tabelle zeigen, die schon existiert. Ebenso kommt besitzer vor tier.

Wo die Fremdschlüssel stehen, folgt aus den Kardinalitäten (LF5, Kapitel 5.3.2 und 5.3.3): Besitzer zu Tier ist 1:n, deshalb steht der Fremdschlüssel in tier. Tier zu Impfstoff ist n:m, deshalb gibt es die Zwischentabelle impfung.

Referenzielle Integrität

Mit FOREIGN KEY … REFERENCES prüft das DBMS die referenzielle Integrität: Ein Tier mit einer Besitzernummer, die es nicht gibt, lässt sich nicht speichern. Was beim Löschen einer Besitzerin mit Tieren passiert, legst du mit einer Regel fest:

RegelWirkung beim Löschen der Besitzerin
ohne Angabe, NO ACTION oder RESTRICTLöschen wird abgelehnt, solange noch Tiere auf sie verweisen
ON DELETE CASCADEihre Tiere werden mitgelöscht
ON DELETE SET NULLbei ihren Tieren wird besitzer_id leer (geht nur ohne NOT NULL)

Für die Praxis ist die Ablehnung richtig: Tier- und Impfdaten sollen nicht verschwinden, nur weil jemand einen Besitzer löscht.

Ändern und löschen

ALTER TABLE tier ADD COLUMN chipnummer CHAR(15) UNIQUE;
ALTER TABLE impfstoff DROP COLUMN hersteller;
DROP TABLE impfliste_alt;

ALTER TABLE ändert die Struktur einer bestehenden Tabelle, etwa um eine Spalte hinzuzufügen oder zu entfernen. DROP TABLE löscht die Tabelle mitsamt allen Daten. Rückgängig machen lässt sich das meist nicht; sichere die Daten vorher.

Beispiel

Die Auszubildende speichert alle CREATE TABLE-Befehle in einer Skriptdatei. Sie führt das Skript zuerst auf dem Testserver aus. Dort bricht es ab: Die Tabelle impfung stand vor impfstoff. Sie löscht die bereits angelegten Tabellen besitzer und tier wieder, stellt die Reihenfolge um, führt das Skript erneut aus und kann es danach unverändert auf dem echten Server verwenden.

„DROP TABLE und DELETE FROM tun dasselbe.“ DELETE FROM tier löscht die Zeilen, die Tabelle bleibt leer bestehen. DROP TABLE tier entfernt die Tabelle selbst mit Struktur und Daten.

Mit DDL legst du die Struktur fest: CREATE TABLE mit Datentypen, Constraints, Primär- und Fremdschlüssel, ALTER TABLE zum Ändern, DROP TABLE zum Löschen; Fremdschlüssel sichern die referenzielle Integrität.
