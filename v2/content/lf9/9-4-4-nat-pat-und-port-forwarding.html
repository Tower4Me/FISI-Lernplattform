Die privaten Adressen 10.x.x.x werden im Internet nicht weitergeleitet. Damit die Praxis-PCs trotzdem Webseiten erreichen und die Web-API der Termin-App im Stammhaus von außen erreichbar ist, setzt der Router Adressen und Ports um. Das Prinzip kennst du aus LF3, Kapitel 3.4.3; hier schaust du dir an, was sich im Paket genau ändert.

Ausgehend: PAT

Der Router im Stammhaus hat eine öffentliche IPv4-Adresse, 198.51.100.10. Viele interne Geräte teilen sie sich. Dafür ersetzt der Router bei jedem ausgehenden Paket die private Absenderadresse durch seine öffentliche und, falls nötig, den Absenderport durch einen freien Port. Diese Form heißt PAT (Port Address Translation), auch NAT-Overload oder Masquerading. Reines NAT ohne Ports setzt dagegen eine Adresse auf genau eine andere um.

Eingehend: Port-Forwarding

Von außen kann niemand ein internes Gerät von sich aus ansprechen, denn es gibt noch keinen Eintrag in der NAT-Tabelle. Soll ein Dienst erreichbar sein, legst du eine feste Weiterleitung an: Pakete an eine öffentliche Adresse und einen Port gehen an eine interne Adresse und einen Port. Das heißt Port-Forwarding oder Destination NAT (DNAT), weil die Zieladresse umgeschrieben wird.

Die Quelle bleibt erhalten; der Server sieht, von wem die Anfrage kommt. Jede Weiterleitung öffnet einen Weg ins interne Netz. Deshalb leitest du nur, was nötig ist, und nie direkt an den Datenbankserver; davor steht ein Dienst wie die Web-API (LF8, Kapitel 8.4.3). Bei der Antwort schreibt der Router die Quelle wieder auf seine öffentliche Adresse zurück.

Warum öffentlich erreichbare Server besser in einem eigenen Netzbereich (DMZ) stehen, wird in LF11b, Kapitel 11.4.2 ausführlicher behandelt.

NAT und IPv6, CGNAT

Mit IPv6 kann jedes Gerät eine öffentliche Adresse haben, NAT ist dort nicht nötig und unüblich; ein Dienst wird erreichbar, indem die Firewall den Zugriff erlaubt. Bei Carrier-Grade NAT (Kapitel 9.1.3) setzt bereits der Anbieter um, oft zusätzlich zum eigenen Router. Eine Weiterleitung im eigenen Router nützt dann nichts, weil die Anfrage den Router gar nicht erreicht.

Beispiel

Die Web-API der Termin-App (LF8, Kapitel 8.4.3) läuft auf 10.10.0.148 im Server-VLAN. Die Auszubildende richtet im Router eine Weiterleitung von 198.51.100.10:443 auf 10.10.0.148:443 ein, nur für HTTPS. Den Datenbankserver 10.10.0.146 leitet sie nicht weiter; die API greift intern auf ihn zu. Ein Test von einem Smartphone im Mobilfunknetz zeigt: Die App erreicht die API, ein Zugriff auf andere Ports scheitert.

„NAT ist eine Firewall.“ NAT verhindert nur, dass ohne Eintrag Verbindungen von außen ankommen. Es prüft keine Inhalte, und mit jeder Weiterleitung ist der Dienst dahinter offen. Den Schutz übernimmt die Firewall.

  • PAT (ausgehend): Router ersetzt private Quell-IP und Quellport durch öffentliche Adresse und freien Port und merkt sich die Zuordnung.
  • Port-Forwarding/DNAT (eingehend): feste Weiterleitung von öffentlicher Adresse und Port auf ein internes Ziel; nur das Nötige weiterleiten.
