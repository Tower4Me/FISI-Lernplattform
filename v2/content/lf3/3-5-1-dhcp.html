Bei zwei Geräten kannst du Adressen noch von Hand eintragen. Sobald Notebooks, Smartphones und Gäste dazukommen, wird das fehleranfällig: doppelte Adressen, falsche Gateways. DHCP verteilt die Konfiguration automatisch und an einer Stelle. Deshalb ist es in fast jedem Netz eingeschaltet, meist im Router.

Was DHCP verteilt

Ein DHCP-Server (Dynamic Host Configuration Protocol) gibt einem Client auf Anfrage eine vollständige IPv4-Konfiguration:

  • IP-Adresse und Subnetzmaske
  • Standardgateway
  • DNS-Server (Kapitel 3.5.2)
  • die Lease-Zeit: wie lange der Client die Adresse nutzen darf

Der Server vergibt Adressen aus einem festgelegten Bereich (Pool), etwa 192.168.10.100 bis 192.168.10.199. Adressen außerhalb des Bereichs bleiben für Geräte mit fester Adresse frei, etwa Router, NAS und Drucker.

Ablauf: DORA

Ein neuer Client kennt weder seine Adresse noch den Server. Deshalb beginnt er mit einem Broadcast:

  1. Discover: Der Client fragt per Broadcast ins Netz: „Gibt es einen DHCP-Server?“
  2. Offer: Der Server bietet eine freie Adresse samt Konfiguration an.
  3. Request: Der Client fordert die angebotene Adresse an; weil mehrere Server geantwortet haben könnten, ebenfalls per Broadcast.
  4. Acknowledge: Der Server bestätigt, der Client richtet die Adresse ein.

Nach der Hälfte der Lease-Zeit bittet der Client seinen Server direkt (Unicast), die Lease zu verlängern; dafür reichen Request und Acknowledge. Antwortet der Server nicht, fragt der Client nach 87,5 % der Lease-Zeit per Broadcast jeden DHCP-Server. Läuft die Lease ab, muss er die Adresse aufgeben. DHCP läuft über UDP, der Server lauscht auf Port 67, der Client auf Port 68.

Weil Discover ein Broadcast ist, erreicht er nur das eigene Netz. Steht der Server in einem anderen Netz, leitet ein DHCP-Relay im Router die Anfragen weiter. Antwortet kein DHCP-Server, gibt sich der Client eine 169.254er-Adresse (APIPA, Kapitel 3.4.5).

Reservierung

Soll ein Gerät immer dieselbe Adresse bekommen, aber trotzdem per DHCP eingerichtet werden, legst du im Server eine Reservierung an: eine feste Zuordnung von MAC-Adresse zu IP-Adresse. Das ist praktisch für Drucker, deren Adresse sich nicht ändern darf, die aber zentral verwaltet werden sollen. Viele Router erlauben Reservierungen auch außerhalb des Bereichs; bei Windows Server muss die Adresse im Bereich liegen. Nutzt ein Gerät im WLAN eine zufällige MAC-Adresse, greift die Reservierung nicht; diese Funktion schaltest du dafür ab (Kapitel 3.3.5).

Beispiel

Nach dem Engpass aus Kapitel 3.4.5 legt die Auszubildende die DHCP-Einstellungen im Router neu fest: Bereich 192.168.10.100 bis .199 (100 Adressen), Gateway und DNS-Server 192.168.10.1, Lease-Zeit ein Tag. Router (.1), Access Point (.5), NAS (.10) und Drucker (.20) liegen außerhalb des Bereichs. Für den Drucker legt sie zusätzlich eine Reservierung auf seine MAC-Adresse an, damit er die .20 auch bekommt, wenn jemand ihn auf „automatisch“ zurückstellt.

„Zwei DHCP-Server sind doppelt sicher.“ Nicht ohne Abstimmung: Verteilen zwei Server im selben Netz Adressen aus überlappenden Bereichen, entstehen doppelte Adressen. Ein vergessener zweiter DHCP-Server, etwa in einem mitgebrachten WLAN-Router, ist ein typischer Störenfried.

  • DHCP verteilt Adresse, Maske, Gateway, DNS-Server und Lease-Zeit aus einem Bereich.
  • DORA: Discover (Broadcast), Offer, Request, Acknowledge; UDP 67/68; feste Zuordnung per Reservierung über die MAC-Adresse.
