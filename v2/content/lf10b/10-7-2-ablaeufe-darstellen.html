Bevor die Auszubildende ein Skript schreibt, das jeden Morgen die Sicherungsmeldungen auswertet, will der Ausbilder den Ablauf sehen, ohne PowerShell lesen zu müssen. Dafür gibt es zwei genormte grafische Darstellungen: den Programmablaufplan (PAP) und das Struktogramm. Pseudocode für denselben Zweck kennst du aus LF5, Kapitel 5.4.2.

Der Ablauf

fehler ← 0
FOR i ← 0 TO LENGTH(protokoll) - 1
    IF protokoll[i]["status"] == "Fehler" THEN
        fehler ← fehler + 1
    END IF
END FOR
IF fehler > 0 THEN
    OUTPUT "Fehlerhafte Sicherungen: ", fehler   // als Mail an den Support
END IF

Programmablaufplan

Der PAP (Symbole nach DIN 66001) zeigt den Ablauf als Fluss mit Pfeilen. Oval: Start und Ende. Rechteck: Anweisung. Raute: Verzweigung mit zwei beschrifteten Ausgängen. Parallelogramm: Ein- oder Ausgabe. Eine Schleife entsteht, indem ein Pfeil zu einer früheren Raute zurückführt.

Struktogramm

Das Struktogramm (Nassi-Shneiderman-Diagramm, DIN 66261) kommt ohne Pfeile aus. Der Ablauf besteht aus Blöcken, die von oben nach unten gelesen werden. Eine Verzweigung ist ein Block mit Dreieck und zwei Spalten für ja und nein. Eine Schleife umschließt ihren Rumpf mit einem Rahmen: steht die Bedingung oben, ist sie kopfgesteuert (prüft vor jedem Durchlauf), steht sie unten, fußgesteuert (Rumpf läuft mindestens einmal). Sprünge gibt es nicht, das erzwingt eine klare Struktur.

„Im Struktogramm zeichne ich einen Pfeil zurück für die Schleife.“ Pfeile gibt es nur im PAP. Im Struktogramm umschließt der Schleifenblock seinen Rumpf; der Rücksprung ist darin enthalten.

  • PAP: Oval Start/Ende, Rechteck Anweisung, Raute Verzweigung, Parallelogramm Ein-/Ausgabe, Pfeile; Schleife als Pfeil zurück.
  • Struktogramm: Blöcke ohne Pfeile, Verzweigung mit Dreieck und Ja-/Nein-Spalte, Schleife als Rahmen, kopf- oder fußgesteuert.
