Der Reverse Proxy der Termin-App nimmt Anfragen aus dem ganzen Internet an (LF9, Kapitel 9.5.4). Bisher steht er im Server-VLAN neben der Datenbank. Findet ein Angreifer eine Lücke im Proxy, sitzt er mitten im internen Netz. Eine DMZ (demilitarisierte Zone) verhindert das: ein eigener Netzbereich für Systeme, die von außen erreichbar sein müssen, getrennt vom Internet und vom internen Netz.

Das Prinzip

Die Firewall regelt den Verkehr zwischen drei Zonen. Grundregel: Von außen darf man nur in die DMZ, nie direkt ins interne Netz. Aus der DMZ darf nur das ins interne Netz, was der Dienst zwingend braucht.

Internet–nur die veröffentlichten Dienste, etwa TCP 443 zum Proxygesperrt

internes Netznach RegelwerkVerwaltung der DMZ-Systeme–

Wird ein System in der DMZ übernommen, kommt der Angreifer von dort nur über die wenigen erlaubten Wege weiter, und die Firewall protokolliert jeden Versuch.

Bauformen

  • Eine Firewall mit drei Schnittstellen (Internet, DMZ, intern): günstig und für kleinere Betriebe üblich. Wird die Firewall selbst überwunden, fällt der Schutz für beide Zonen.
  • Zwei hintereinander geschaltete Firewalls, die DMZ liegt dazwischen: Ein Angreifer muss zwei Systeme überwinden, besonders sicher, wenn sie von verschiedenen Herstellern stammen. Teurer und aufwendiger.

Was in die DMZ gehört

In die DMZ gehören Systeme, die direkt aus dem Internet angesprochen werden: Reverse Proxy, öffentlicher Webserver, Mail-Gateway, das Mails annimmt und prüft, VPN-Zugänge. Daten mit hohem Schutzbedarf wie die Praxisdatenbank gehören nicht hinein; der Dienst in der DMZ holt sich nur, was er braucht, über eine eng erlaubte Verbindung.

Beispiel

Das Systemhaus richtet an der neuen Firewall im Stammhaus eine dritte Schnittstelle für die DMZ ein: VLAN 70 mit 10.10.0.160/28 aus dem freien Bereich des Adressplans (LF9, Kapitel 9.3.1). Der Reverse Proxy läuft weiter als VM auf den Hosts aus LF10b, Kapitel 10.1.2; die Hosts bekommen VLAN 70 nur für diese VM, ihre Adresse wechselt von 10.10.0.149 auf 10.10.0.162. Die Adressen der übrigen Server bleiben hier zur Übersicht die aus LF9. Erlaubt sind nur: Internet zum Proxy auf TCP 443 (die Weiterleitung von 198.51.100.10:443 zeigt jetzt auf 10.10.0.162), Proxy zur Web-API 10.10.0.148 auf TCP 443, Proxy ins Internet auf TCP 443 für Updates und die ACME-Erneuerung (Kapitel 11.3.2) mit DNS über einen öffentlichen Resolver, Verwaltung aus dem Management-VLAN 99 zum Proxy per SSH. Die Web-API bleibt im Server-VLAN; aus der DMZ darf nur sie angesprochen werden, nicht die Datenbank. Ein Test von der DMZ aus zeigt: Der Proxy erreicht weder die Datenbank noch die PCs der Verwaltung.

Eine DMZ-VM auf demselben Host wie interne Server spart Geräte. Eine Lücke im Hypervisor würde die Trennung aber aufheben. Bei hohem Schutzbedarf bekommt die DMZ eigene Hardware.

„Der Webserver steht in der DMZ, also kann er auch die Datenbank direkt abfragen.“ Genau diese Verbindung soll die DMZ verhindern oder auf das Nötigste beschränken. Die Datenbank bleibt intern, und zwischen DMZ und intern erlaubt die Firewall nur einzelne, begründete Wege.

  • DMZ: eigener Netzbereich für Systeme, die von außen erreichbar sind; von außen nur in die DMZ, aus der DMZ nur eng begrenzte Wege nach innen.
  • Bauformen: eine Firewall mit drei Schnittstellen (günstig) oder zwei Firewalls hintereinander (sicherer); schützenswerte Daten bleiben im internen Netz.
