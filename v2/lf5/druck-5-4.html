5.4Algorithmen und Programme

AP1LF5: Software zur Verwaltung von Daten anpassen

5.4.1 Programme und Sprachen

Die Tierarztpraxis möchte, dass ihre Software Rechnungen selbst addiert und an fällige Impfungen erinnert. Dazu muss jemand dem Computer genau sagen, was in welcher Reihenfolge zu tun ist. Das ist ein Algorithmus. In einer Programmiersprache aufgeschrieben, wird daraus ein Programm.

Algorithmus, Quellcode, Programm#

Ein Algorithmus ist eine eindeutige Folge von Schritten, die ein Problem löst. Er ist endlich beschrieben, jeder Schritt ist ausführbar, und er kommt nach endlich vielen Schritten zu einem Ergebnis. Ein Kochrezept ist ein Algorithmus für Menschen; „Addiere alle Positionen der Rechnung“ ist einer für den Computer.

Schreibst du den Algorithmus in einer Programmiersprache auf, entsteht Quellcode: lesbarer Text mit festen Regeln (Syntax). Der Prozessor versteht nur Maschinencode. Deshalb muss der Quellcode übersetzt oder von einem Programm ausgeführt werden, das ihn versteht.

Compiler und Interpreter#

CompilerInterpreter
Arbeitsweiseübersetzt den ganzen Quellcode vorab in eine ausführbare Dateiliest den Quellcode beim Ausführen und führt ihn Anweisung für Anweisung aus
Fehler im CodeSyntaxfehler werden beim Übersetzen gemeldet, das Programm entsteht erst danachviele Fehler fallen erst auf, wenn die Stelle ausgeführt wird
Ausführungschnell, Quellcode wird nicht mitgeliefert; die Datei läuft nur auf der Plattform, für die übersetzt wurdelangsamer, Interpreter muss auf dem Zielrechner vorhanden sein
BeispieleC, C++, GoPython, PHP, JavaScript (klassisch)

Viele Sprachen mischen beide Wege: Java und C# übersetzen in einen Zwischencode (Bytecode), den eine Laufzeitumgebung auf dem Zielrechner ausführt und dabei teils weiter übersetzt.

Programmiersprache oder nicht?#

Eine Programmiersprache kann Abläufe steuern: Werte in Variablen speichern, rechnen, verzweigen und wiederholen. Andere Sprachen in der IT beschreiben nur etwas:

  • Auszeichnungssprache (Markup): HTML legt fest, was auf einer Webseite Überschrift, Absatz oder Link ist. XML strukturiert Daten (Kapitel 5.2.2).
  • Stylesheet-Sprache: CSS beschreibt, wie die Elemente aussehen, also Farben, Schriften, Abstände.
  • Abfragesprache: SQL beschreibt, welche Daten aus einer Datenbank gewünscht sind, nicht wie sie gesucht werden.

HTML und CSS sind also keine Programmiersprachen. JavaScript dagegen ist eine; es läuft im Browser und macht eine Seite interaktiv.

Statische und dynamische Webseiten#

Eine statische Webseite liegt als fertige Datei auf dem Webserver und wird bei jedem Aufruf gleich ausgeliefert. Eine dynamische Webseite wird bei jedem Aufruf ganz oder teilweise neu erzeugt, meist von einem Programm auf dem Server mit Daten aus einer Datenbank, oder im Browser per JavaScript. Statische Seiten sind schnell und bieten wenig Angriffsfläche; dynamische zeigen aktuelle und persönliche Inhalte, brauchen aber eine Laufzeitumgebung und mehr Pflege.

Beispiel

Die Seite mit Öffnungszeiten und Anfahrt der Praxis ändert sich selten und ist für alle Besucher gleich: statisch genügt. Die Online-Terminbuchung muss freie Termine aus der Datenbank lesen und Buchungen speichern: Sie ist dynamisch.

Programmierparadigmen#

Ein Paradigma ist ein Denkstil beim Programmieren. Imperativ bzw. prozedural beschreibst du Schritt für Schritt, wie etwas passiert, gegliedert in Funktionen. Objektorientiert bündelst du Daten und die passenden Funktionen in Objekten. Den Bauplan liefert eine Klasse, etwa „Tier“ mit den Attributen name und gewicht und der Methode gewichtErfassen(); Mimi und Bello sind zwei Objekte (Instanzen) dieser Klasse. Kapselung heißt, dass andere Programmteile die Attribute nur über Methoden ändern; durch Vererbung übernimmt eine Klasse „Hund“ alles von „Tier“ und ergänzt Eigenes. Deklarativ beschreibst du nur das gewünschte Ergebnis, wie bei SQL. Viele Sprachen wie Python oder Java erlauben mehrere Stile. Die folgenden Kapitel arbeiten imperativ.

Eine Sprache auswählen#

Welche Sprache für ein Vorhaben passt, entscheidet nicht Vorliebe, sondern der Zweck. Typische Kriterien:

  • Einsatzgebiet und Plattform: Webanwendung, App, Skript zur Verwaltung von Servern, Auswertung von Daten.
  • Vorhandenes Wissen im Team und bei denen, die die Software später warten.
  • Bibliotheken und Werkzeuge: Gibt es fertige Bausteine, etwa für Datenbanken oder Schnittstellen?
  • Zusammenspiel mit vorhandenen Systemen, etwa der Praxissoftware.
  • Geschwindigkeit, wo sie wichtig ist, etwa bei großen Datenmengen.
  • Verbreitung und Zukunft: aktive Weiterentwicklung, Hilfe in Foren, Fachkräfte auf dem Markt; dazu Kosten für Lizenzen und Entwicklungsumgebung.

Häufiger Fehler

„Wer eine Webseite in HTML schreibt, programmiert.“ HTML beschreibt nur Struktur und Inhalt; es steuert keine Abläufe mit Verzweigungen oder Schleifen. Programmiert wird erst mit einer Sprache wie JavaScript oder PHP.

Merksatz

  • Übersetzung: Ein Compiler übersetzt den Quellcode vorab ganz, ein Interpreter führt ihn beim Ausführen Anweisung für Anweisung aus.
  • Sprachen: HTML (Auszeichnung) und CSS (Gestaltung) sind keine Programmiersprachen; sie beschreiben Struktur und Aussehen, steuern aber keine Abläufe mit Verzweigungen oder Schleifen.

5.4.2 Pseudocode, Variablen und Operatoren

Bevor das Systemhaus die Praxissoftware ändert, einigt es sich mit der Praxis auf den Ablauf, und zwar so, dass ihn auch jemand ohne Kenntnis der Programmiersprache lesen kann. Dafür gibt es Pseudocode. Seine Bausteine sind Variablen, Zuweisungen und Operatoren.

Pseudocode#

Pseudocode beschreibt einen Algorithmus in einer Mischung aus Programmiersprache und Klartext. Er ist nicht genormt und wird nicht ausgeführt, sondern dient dem Entwurf und der Verständigung. Wichtig ist nur, dass der Ablauf eindeutig ist und die Schreibweise innerhalb eines Dokuments gleich bleibt. In der Prüfung sind englische Schlüsselwörter üblich. Diese Lernplattform verwendet durchgehend folgende Schreibweise:

BausteinSchreibweise
Zuweisungsumme ← 0
Ein- und AusgabeINPUT gewicht, OUTPUT "Text", wert
VerzweigungIF … THEN … ELSE IF … THEN … ELSE … END IF
SchleifenFOR i ← 0 TO n - 1 … END FOR, WHILE … DO … END WHILE, DO … WHILE …
FunktionFUNCTION name(parameter) … RETURN wert … END FUNCTION
Datenstrukturenwerte ← [4, 7, 2], Zugriff werte[0]; tier ← {"name": "Mimi"}, Zugriff tier["name"]
SonstigesTRUE, FALSE, LENGTH(liste) für die Anzahl der Elemente (bei Text: der Zeichen), + verbindet auch Texte, // Kommentar

Eingerückt wird alles, was zu einem Block gehört. Verzweigungen und Schleifen folgen in Kapitel 5.4.3, Funktionen in Kapitel 5.4.4.

Variablen und Zuweisung#

Eine Variable ist ein benannter Speicherplatz für einen Wert, der sich im Lauf des Programms ändern kann. Ihr Datentyp legt fest, welche Werte sie aufnehmen kann (Kapitel 5.1.4). Gute Namen sagen, was drinsteht: nettobetrag statt x.

Die Zuweisung variable ← ausdruck rechnet zuerst die rechte Seite aus und speichert das Ergebnis dann in der Variablen links. Der alte Wert wird dabei überschrieben. anzahl ← anzahl + 1 ist deshalb keine Gleichung, sondern heißt: Nimm den aktuellen Wert, addiere 1, speichere das Ergebnis wieder in anzahl.

Operatoren#

ArtOperatorenErgebnis
arithmetisch+ - * /, DIV (ganzzahlige Division), MOD (Rest)Zahl: 17 DIV 5 ergibt 3, 17 MOD 5 ergibt 2
Vergleich== != < <= > >=Wahrheitswert: 4 >= 4 ist TRUE
logischAND OR NOTWahrheitswert

a AND b ist nur wahr, wenn beide Teile wahr sind. a OR b ist wahr, sobald mindestens ein Teil wahr ist. NOT a kehrt den Wert um.

Die Reihenfolge: Zuerst Klammern, dann Punkt- vor Strichrechnung (DIV und MOD zählen als Punktrechnung), dann Vergleiche, dann NOT, AND und zuletzt OR. Wo NOT genau steht, unterscheidet sich zwischen Sprachen. 7 + 3 * 2 ergibt 13, (7 + 3) * 2 ergibt 20. Setze im Zweifel Klammern; sie kosten nichts und machen die Absicht klar.

Beispiel

Die Praxis rechnet eine Behandlung mit 80,00 € netto ab, darauf kommen 19 % Umsatzsteuer:

netto ← 80.00
steuer ← netto * 0.19
brutto ← netto + steuer
OUTPUT "Rechnungsbetrag: ", brutto

Nach der zweiten Zeile enthält steuer den Wert 15.20, nach der dritten brutto den Wert 95.20. Ausgegeben wird der Rechnungsbetrag von 95,20 €.

Häufiger Fehler

„= und == sind dasselbe.“ In vielen Sprachen weist = einen Wert zu, während == zwei Werte vergleicht. Wer in einer Bedingung versehentlich zuweist, verändert die Variable, statt sie zu prüfen. Der Pfeil ← im Pseudocode vermeidet diese Verwechslung.

Merksatz

Eine Zuweisung rechnet erst die rechte Seite aus und speichert das Ergebnis dann links; Vergleiche und logische Operatoren (AND, OR, NOT) liefern einen Wahrheitswert.

5.4.3 Verzweigungen und Schleifen

Ein Programm, das Zeile für Zeile durchläuft, kann noch nicht viel. Die Impferinnerung der Praxis muss entscheiden, ob eine Impfung fällig ist, und die Rechnung muss jede Position einmal anfassen, egal wie viele es sind. Dafür gibt es Verzweigungen und Schleifen.

Verzweigungen#

Eine Verzweigung führt Anweisungen nur aus, wenn eine Bedingung wahr ist. Die einseitige Form hat nur einen THEN-Teil, die zweiseitige zusätzlich einen ELSE-Teil für den Fall „falsch“. Gibt es mehr als zwei Fälle, hängst du weitere Bedingungen mit ELSE IF an (kaskadiert): Geprüft wird von oben nach unten, ausgeführt wird nur der erste Zweig, dessen Bedingung zutrifft.

Beispiel

Eine Impfung soll in diesem Beispiel nach 365 Tagen aufgefrischt werden. Die Software zeigt einen Status abhängig von den Tagen seit der letzten Impfung:

IF tage > 365 THEN
    status ← "überfällig"
ELSE IF tage > 335 THEN
    status ← "bald fällig"
ELSE
    status ← "aktuell"
END IF

Bei 350 Tagen ist die erste Bedingung falsch, die zweite wahr: Status „bald fällig“. Bei 400 Tagen greift schon der erste Zweig („überfällig“), bei 120 Tagen keiner der beiden, also „aktuell“.

Die Reihenfolge der Bedingungen zählt. Stünde tage > 335 oben, bekäme ein Tier mit 400 Tagen den Status „bald fällig“, denn 400 ist auch größer als 335, und der Zweig „überfällig“ würde nie erreicht.

Steht eine Verzweigung innerhalb einer anderen, heißt sie verschachtelt, etwa: IF tierart == "Hund" THEN IF gewicht > 20 THEN …. Oft lässt sich das mit AND zu einer Bedingung zusammenfassen. Vergleichst du eine Variable mit vielen festen Werten, bieten viele Sprachen eine Mehrfachauswahl (switch, CASE): Zum Wert „Hund“, „Katze“ oder „Vogel“ gibt es je einen Zweig, für alle anderen einen Standardzweig.

Schleifen#

SchleifePrüfungEinsatz
WHILE bedingung DO … END WHILEkopfgesteuert: vor jedem Durchlauf; ist die Bedingung gleich zu Beginn falsch, läuft sie keinmalAnzahl der Durchläufe vorher unbekannt
DO … WHILE bedingungfußgesteuert: nach jedem Durchlauf; läuft mindestens einmalEingabe so lange wiederholen, bis sie gültig ist
FOR i ← 0 TO n - 1 … END FORZählschleife: Zählvariable läuft von Start- bis einschließlich EndwertAnzahl bekannt, etwa alle Elemente einer Liste

Beispiel

Eine Besitzerin zahlt eine Operation über 250 € in Monatsraten zu 60 €. Wie viele Monate dauert das?

rest ← 250
monate ← 0
WHILE rest > 0 DO
    rest ← rest - 60
    monate ← monate + 1
END WHILE
OUTPUT monate

rest nimmt nacheinander die Werte 190, 130, 70, 10 und −50 an. Danach ist rest > 0 falsch, die Schleife endet, ausgegeben wird 5. Die fünfte Rate beträgt in Wirklichkeit nur 10 €; das müsste die Ausgabe gesondert behandeln.

Eine Endlosschleife entsteht, wenn die Bedingung nie falsch wird. Fehlt im Beispiel die Zeile rest ← rest - 60, bleibt rest bei 250 und das Programm hängt. In jeder WHILE-Schleife muss sich also etwas ändern, das die Bedingung beeinflusst.

Hinweis

„Von 0 bis n − 1“ hat einen Grund: Listen zählen ihre Elemente meist ab 0 (Kapitel 5.4.4). Eine Liste mit 3 Elementen hat die Positionen 0, 1 und 2.

Vertiefung

Wird in LF10b ausführlicher behandelt. Dort werden dieselben Abläufe grafisch als Programmablaufplan (PAP) und Struktogramm dargestellt und entworfen.

Merksatz

  • Verzweigung: Bei IF … ELSE IF … ELSE gewinnt der erste zutreffende Zweig, deshalb zählt die Reihenfolge der Bedingungen.
  • Schleifen: WHILE prüft vorher (eventuell kein Durchlauf), DO … WHILE prüft nachher (mindestens ein Durchlauf), FOR zählt; ändert sich die Bedingung nie, entsteht eine Endlosschleife.

5.4.4 Datenstrukturen und Funktionen

Die Praxis hat nicht ein Tier, sondern hunderte. Für jedes eine eigene Variable anzulegen, ginge nicht. Datenstrukturen fassen viele Werte unter einem Namen zusammen, Funktionen fassen Abläufe zusammen, die immer wieder gebraucht werden.

Array und Liste#

Ein Array speichert eine feste Anzahl von Werten hintereinander unter einem Namen. Jeder Wert hat eine Position, den Index. In den meisten Sprachen (C, Java, Python, JavaScript) und auf dieser Plattform wird ab 0 gezählt: Bei n Elementen läuft der Index von 0 bis n − 1. Legt eine Aufgabe einen anderen Startindex fest, gilt die Aufgabe. Eine Liste ist dasselbe Prinzip, kann aber zur Laufzeit wachsen und schrumpfen; in vielen Sprachen wie Python heißt das, was umgangssprachlich Array heißt, Liste.

gewichte ← [4.35, 12.4, 3.8]
OUTPUT gewichte[0]          // 4.35
OUTPUT gewichte[2]          // 3.8
OUTPUT LENGTH(gewichte)     // 3

Ein Zugriff auf gewichte[3] wäre ein Fehler: Das dritte Element hat den Index 2, ein Element mit Index 3 gibt es nicht.

Dictionary#

Ein Dictionary (auch Map oder assoziatives Array) speichert Paare aus Schlüssel und Wert. Du greifst nicht über eine Position zu, sondern über den Schlüssel. Das passt zu einem Datensatz mit benannten Feldern, ähnlich einem JSON-Objekt (Kapitel 5.2.2).

tier ← {"name": "Bello", "art": "Hund", "gewicht": 12.4}
OUTPUT tier["art"]          // Hund

Array aus Dictionaries#

Kombiniert ergibt das eine Tabelle im Speicher: ein Array, dessen Elemente Dictionaries sind. Ein Element steht für eine Zeile, die Schlüssel für die Spalten. Zugegriffen wird in zwei Schritten: erst der Index, dann der Schlüssel.

tiere ← [
    {"name": "Mimi",  "art": "Katze",         "gewicht": 4.35},
    {"name": "Bello", "art": "Hund",          "gewicht": 12.4},
    {"name": "Luna",  "art": "Katze",         "gewicht": 3.8},
    {"name": "Kiki",  "art": "Wellensittich", "gewicht": 0.04}
]
OUTPUT tiere[1]["name"]     // Bello

Zweidimensionales Array#

Ein Array kann selbst Arrays enthalten. So entsteht eine Tabelle aus Zeilen und Spalten, ein zweidimensionales Array. Der erste Index wählt die Zeile, der zweite die Spalte. Durchlaufen wird es mit zwei verschachtelten Schleifen: Die äußere geht die Zeilen durch, die innere für jede Zeile alle Spalten.

Beispiel

Die Praxis zählt Termine je Behandlungsraum (Zeile 0 und 1) an drei Tagen (Spalte 0 bis 2):

belegung ← [
    [3, 5, 2],
    [4, 0, 6]
]
summe ← 0
FOR z ← 0 TO 1
    FOR s ← 0 TO 2
        summe ← summe + belegung[z][s]
    END FOR
END FOR
OUTPUT summe                // 20

Die innere Schleife läuft für jede Zeile vollständig durch, der Rumpf wird also 2 × 3 = 6-mal ausgeführt. belegung[1][2] ist der Wert in Zeile 1, Spalte 2, also 6.

Funktionen#

Eine Funktion ist ein benannter Programmteil, der eine Aufgabe erledigt. Sie bekommt Werte über Parameter und liefert mit RETURN einen Rückgabewert an die aufrufende Stelle. RETURN beendet die Funktion sofort. Einmal geschrieben, lässt sie sich mit beliebigen Werten aufrufen. Ein Programmteil ohne Rückgabewert heißt oft Prozedur.

Beispiel

Die Praxis möchte wissen, wie viele Tiere einer Art sie betreut:

FUNCTION zaehleArt(tiere, gesucht)
    anzahl ← 0
    FOR i ← 0 TO LENGTH(tiere) - 1
        IF tiere[i]["art"] == gesucht THEN
            anzahl ← anzahl + 1
        END IF
    END FOR
    RETURN anzahl
END FUNCTION

Mit der Liste oben liefert zaehleArt(tiere, "Katze") den Wert 2 (Mimi und Luna), zaehleArt(tiere, "Hund") den Wert 1 und zaehleArt(tiere, "Pferd") den Wert 0. Den Rückgabewert bestimmst du, indem du den Aufruf mit genau diesen Werten Schritt für Schritt durchgehst (Kapitel 5.4.5).

Call by Value und Call by Reference#

Bei Call by Value erhält die Funktion eine Kopie des Werts. Ändert sie den Parameter, bleibt die Variable des Aufrufers unverändert. Bei Call by Reference erhält sie einen Verweis auf die Variable des Aufrufers. Eine Änderung in der Funktion wirkt dann direkt auf diese Variable.

FUNCTION erhoehe(zahl)
    zahl ← zahl + 1
END FUNCTION

x ← 5
erhoehe(x)
OUTPUT x      // Call by Value: 5, Call by Reference: 6

Hinweis

Java übergibt einfache Werte wie int als Kopie, bei Arrays und Objekten einen Verweis als Wert. Python übergibt immer einen Verweis als Wert; Zahlen und Texte lassen sich aber nicht verändern, deshalb wirkt es bei ihnen wie Call by Value. Das Beispiel erhoehe(x) gibt in beiden Sprachen 5 aus. Ändert eine Funktion dagegen den Inhalt einer übergebenen Liste, etwa ein Element, sieht der Aufrufer die Änderung. Weist sie dem Parameter eine ganz neue Liste zu, bleibt die Liste des Aufrufers unverändert. Echtes Call by Reference bieten etwa C++ (&) und C# (ref).

Merksatz

  • Datenstrukturen: Ein Array greift über den Index ab 0 zu (letzter Index n − 1), ein Dictionary über den Schlüssel; ein Array aus Dictionaries oder ein zweidimensionales Array bildet eine Tabelle ab, durchlaufen mit verschachtelten Schleifen.
  • Funktionen: Parameter bringen Werte hinein, RETURN gibt einen Wert zurück; Call by Value übergibt eine Kopie, Call by Reference einen Verweis auf das Original.

5.4.5 Schreibtischtest und Fehlersuche

Die neue Rechnungsfunktion der Praxissoftware läuft ohne Fehlermeldung, aber jede Rechnung lautet auf 0,00 €. Solche Fehler findet kein Compiler. Du findest sie, indem du den Ablauf mit konkreten Werten nachvollziehst: auf Papier mit einem Schreibtischtest oder am Rechner mit einem Debugger.

Der Schreibtischtest#

Beim Schreibtischtest führst du einen Algorithmus von Hand aus, ohne Computer. Du wählst Testwerte und notierst in einer Trace-Tabelle nach jedem Schritt den aktuellen Wert jeder Variablen. Eine Zeile pro Schritt oder Schleifendurchlauf, eine Spalte pro Variable, bei Bedarf weitere Spalten für Zwischenergebnisse. So siehst du genau, wo ein Wert anders wird als erwartet.

Die Rechnungssumme wird aus Behandlungspositionen berechnet, einem Array aus Dictionaries (Kapitel 5.4.4):

positionen ← [
    {"bezeichnung": "Untersuchung", "preis": 30.00, "menge": 1},
    {"bezeichnung": "Impfung",      "preis": 25.50, "menge": 2},
    {"bezeichnung": "Wurmkur",      "preis": 8.20,  "menge": 3}
]

FUNCTION rechnungssumme(positionen)
    summe ← 0
    FOR i ← 0 TO LENGTH(positionen) - 1
        summe ← summe + positionen[i]["preis"] * positionen[i]["menge"]
    END FOR
    RETURN summe
END FUNCTION
Trace-Tabelle für rechnungssumme(positionen)

Rückgabewert: 105,60 €. Die Schleife läuft genau dreimal, weil LENGTH(positionen) - 1 den Wert 2 ergibt.

Drei Arten von Fehlern#

FehlerWas passiertBeispielSo findest du ihn
SyntaxfehlerCode verletzt die Regeln der Sprache; er lässt sich nicht übersetzen bzw. nicht startenfehlende Klammer, falsch geschriebenes SchlüsselwortCompiler oder Interpreter meldet ihn mit Zeilennummer
LaufzeitfehlerProgramm startet, bricht aber bei einer bestimmten Anweisung abDivision durch 0, Zugriff auf einen Index, den es nicht gibtFehlermeldung beim Ausführen, oft nur bei bestimmten Daten
LogikfehlerProgramm läuft durch, liefert aber ein falsches Ergebnisfalscher Operator, falsche Bedingung, falscher Startwertnur durch Tests mit bekannten Sollwerten, Schreibtischtest, Debugger

Ein Laufzeitfehler entstünde oben mit FOR i ← 0 TO LENGTH(positionen): Im vierten Durchlauf hätte i den Wert 3, aber das letzte Element hat den Index 2.

Beispiel

Zurück zur Rechnung über 0,00 €. In der Schleife steht summe ← summe * positionen[i]["preis"] * positionen[i]["menge"], also Multiplikation statt Addition. Der Schreibtischtest zeigt es sofort: summe startet mit 0, und 0 mal irgendetwas bleibt 0. Nach dem ersten, zweiten und dritten Durchlauf steht in summe jeweils 0, zurückgegeben wird 0. Korrekt ist summe ← summe + …, dann ergibt sich wieder 105,60 €.

Fehlersuche mit dem Debugger#

Ein Debugger ist ein Werkzeug der Entwicklungsumgebung, das ein Programm kontrolliert ausführt. Grundbegriffe:

  • Haltepunkt (Breakpoint): Markierung an einer Zeile; dort hält das Programm an.
  • Einzelschritt (Step): Das Programm führt nur die nächste Anweisung aus und hält wieder an. Du kannst dabei in eine aufgerufene Funktion hineinspringen oder sie in einem Schritt ausführen.
  • Variablen beobachten (Watch): Die aktuellen Werte werden angezeigt, wie in einer Trace-Tabelle, die der Rechner selbst führt.

Für die Rechnungsfunktion setzt du einen Haltepunkt auf die Zeile in der Schleife und beobachtet summe. Bleibt sie nach jedem Einzelschritt bei 0, ist die fehlerhafte Zeile gefunden.

Häufiger Fehler

„Keine Fehlermeldung, also stimmt das Programm.“ Logikfehler erzeugen keine Meldung. Erst der Vergleich mit einem vorher von Hand berechneten Sollwert zeigt, ob das Ergebnis richtig ist. Wie du solche Testfälle planst, folgt in Kapitel 5.6.1.

Merksatz

  • Schreibtischtest: Algorithmus mit Testwerten von Hand ausführen und jeden Variablenwert Schritt für Schritt in einer Trace-Tabelle notieren.
  • Fehlerarten: Syntaxfehler verhindern den Start, Laufzeitfehler brechen das Programm ab, Logikfehler liefern ohne Meldung ein falsches Ergebnis.
